# excel2md 初期設計メモ（参考）

この文書は、初期実装に向けて採用したルール・検討経緯・確認観点を残した設計メモです。以下の「初期」「v1」は設計時点の範囲を表します。現在の実装・拡張手順は [Excelの開発者ガイド](../excel2md.md)、API・設定・対応範囲は [機能README](../../functions/excel2md/README.md)、起動・テスト・配置は [共通の作業手順](../development.md) を参照してください。公開・デプロイの進捗を管理する文書ではありません。

Excelファイルを渡すだけでMarkdownへ変換する。シート名だけをH1にし、H2以降は生成しない。セル罫線から検出した表をMarkdown表に、それ以外のセルを本文にする。本文・表内ともに太字とリンクを保持し、取消線の文字は出力から除外する。貼り付け画像をファイルとして取り出し、基本図形はPNGとして描画して、Markdownから参照する。グラフの描画は初期対象外とする。ファイルごとのルールJSONや範囲指定は要求せず、v1ではその入力機能も設けない。

H1のみ・指定不要・罫線による表検出・太字とリンクの保持・取消線の文字の除外・画像と図形への対応はユーザー指定。以下は採用した設計と確認観点。図形は独自の簡易描画で、Excelの画面との完全一致は対象外。日本語・取消線・回転・グループなどを生成fixtureで検証している。

## 提供単位

- 実装先は独立した `functions/excel2md/`。単独でビルド・起動できる。
- Java 21 / Apache POI。貼り付け画像は埋め込みデータを抽出し、基本図形はJava2Dで描画する。LibreOfficeや商用描画ライブラリは必須にしない。シート全体の描画・PDFBoxには依存しない。
- 図形内文字の描画用に、既存機能と同じNoto日本語フォントをライセンス・出典とともに同梱する。`excel2md` 単独のパッケージに含め、実行時に別の変換機能のディレクトリを参照しない。Markdown本文の出力にはフォントを使わない。
- v1入力は `.xlsx` / `.xls`。実際の内容を検査する。暗号化、`.xlsb`、マクロ有効ブックはv1対象外。
- 出力は1ブックにつき1つのUTF-8 Markdownと画像ファイル群、report。表示シートをブック内の順序で処理する。
- 同期HTTP、HTTP経由の非同期受付、外部システムからの直接Queueを提供する。変換処理は共通。
- 軽量Playgroundはファイルを選んで変換するだけ。Markdown・プレビュー・警告を確認できるようにする。

## 変換の基本ルール

| Excel | Markdown／扱い |
| --- | --- |
| シート名 | `# シート名`。ブック名のH1は付けない |
| シート内のタイトル、大きな文字 | 通常の本文。H2以降へ変換しない |
| 太字 | `**文字**`。セル全体と文字列の一部分の両方に対応 |
| セルに設定されたWeb・メールリンク | `[表示文字](リンク先)`。太字との併用も保持 |
| 取消線の文字 | 本文・表ともに削除。セルの一部分なら該当部分だけ、全体なら空欄 |
| 貼り付け画像 | `images/` に抽出し、`![説明](images/image-0001.png)` で参照 |
| 基本図形・図形内文字 | 対応種類をPNG化し、`![図形1](images/diagram-0001.png)` で参照 |
| セル罫線で区切られた表 | 検出できた範囲をMarkdown表にする |
| 罫線のないセル | 複数列に値が並んでいても本文にする |
| 表外の同じ行の複数セル | 左から右へ、全角スペースで区切る。空セルを埋めるための大量の空白は出さない |
| 表外の行・セル内改行 | 改行を保持。Markdownの改行記法でプレビューにも反映する |
| 表外の空行 | 段落区切り。連続した空行は1つの段落区切りにまとめる |
| 表内の空行・空列・空セル | 位置関係を保って残す。空欄を0などで補わない |
| 本文・リンク・画像がないシート、値がない罫線だけの範囲 | 出力から除外し、結果情報に記録。画像だけのシートは残す |
| 非表示シート・行・列 | 除外し、結果情報に記録 |
| 数値・日付・パーセント・通貨 | セルの表示形式を尊重し、日本語ロケールを既定にする |
| 数式 | 保存済み計算結果。実行時に再計算しない |
| 結合セル | 左上の値を1回だけ出し、他の位置は空欄。値を自動コピーしない |
| 表内のセル内改行 | 生成側の `<br>` に変換 |
| セルの文字色・背景色・斜体・下線・列幅・行高 | Markdownへは反映しない。青色や下線だけからリンクを推測しない |

表・本文・画像をブロックにし、それぞれの開始行、開始列の順に並べる。同じ高さの表は左から右、離れた上下の表は上から下へ出す。表は途中に他の本文を挟まず、一つのブロックとして出力する。表と画像の重なりは後述の画像配置ルールで扱う。雑誌の段組みのような意味上の読む順番は推測しない。

## 罫線による表検出

画像認識は使わず、Excelに保存されたセルの上下左右の罫線を読む。Excel画面の薄いグリッド線、フォントの下線、図形の線は表の根拠にしない。セル罫線の線種・太さ・色の違いだけでは別表に分けない。

v1は次の保守的な判定から始める。具体的な検出器は格子・結合・隣接した表のfixtureで確認し、罫線があるだけで内容の意味まで確定したと扱わない。

1. 書式だけの空セルも含めて罫線を収集する。隣り合うセルの境界は、どちらか一方に線があれば罫線として扱う。
2. 閉じた長方形の外枠と、その中の区画を作る罫線から表候補を作る。基本対象は格子状の表で、結合セルの内部に線がないことは許容する。
3. 単独の下線や、内部の区切りがない一つの囲み枠は本文にする。枠付きタイトルを表にしない。外枠だけの一覧や横線だけの表もv1では本文になり得る。
4. 候補内に値があり、結合を考慮して複数の区画がある場合に表として採用する。格子の全体を一つの表にし、各セルを個別の表として出さない。
5. 表の中の空行・空列は罫線の連続性に従って保持する。罫線のない間隔で分かれた表は別々にする。隙間なく境界を共有する表の意味上の分割は行わない。
6. 外枠が欠ける、範囲が競合するなど、範囲を一意に決められない候補は本文として残し、座標付きで警告する。検出できないセルの値を黙って捨てない。

結合範囲を途中で切る表は採用しない。表は元のシート上で検出してから非表示行・列を除外し、結果情報に元の範囲・除外した座標を残す。非表示の結合アンカーの値を、別の表示セルへ移して出力しない。

条件付き書式やテーブルスタイルだけが生成する罫線は、v1の直接セル罫線による検出の対象外とする。該当する書式がある場合は未評価であることを結果情報に記録する。Excelの「テーブルとして書式設定」も、罫線がなければそれだけを理由にMarkdown表へ変換しない。

### 表のヘッダー

罫線だけでは先頭行が見出しかどうかは確定できない。GFM表にはヘッダー行が必要なので、次のルールで元の行を保持する。

- 検出した表範囲がExcelのテーブル定義と一致し、ヘッダー行が有効なら、その定義を利用する。
- それ以外は空のヘッダー行を生成し、元の先頭行も含めて全行をデータ行として残す。先頭行を削除したり、列名を推測して作ったりしない。
- 太字や色だけではヘッダーへ昇格させない。ヘッダー判定方法を結果情報に記録する。
- 複数段の見出し・結合は通常の行と空欄に展開する。GFMの制約で結合状態は再現できないため、結果情報に結合範囲と警告を保持する。

例えば「売上」シートに本文「2026年度」「金額は税込」と、通常セルの罫線表がある場合は次のようになる。表の「商品」「4月」「5月」は元の先頭行として保持する。

```markdown
# 売上

2026年度

金額は税込

|  |  |  |
| --- | --- | --- |
| 商品 | 4月 | 5月 |
| 商品A | 10,000 | 12,000 |
| 商品B | 8,000 | 9,000 |
```

## 太字・リンク・取消線

いずれも追加指定なしで、本文と表のセルに同じルールを適用する。太字は文字装飾として保持し、見出しや表ヘッダーの自動判定には使わない。

取消線はセルのフォントとrich textの実効書式から判定し、太字・リンクを生成する前に該当文字を除外する。

- 一部分の取消線はその区間だけを削除する。例として「旧価格新価格」のうち「旧価格」だけに取消線があれば「新価格」になる。残す文字・空白・句読点を勝手に補正しない。
- セル全体が取消線なら空欄にする。数値や数式の表示結果にも適用する。表の行・列は削除せず、元の位置に空セルを残す。
- 太字やリンクと重なっていても取消線の除外を優先する。リンクラベルをすべて削除した場合はリンクも出さず、空ラベル時のURL補完で復活させない。
- 部分取消線と表示形式による出力文字列の対応が確定できない場合は、元のrich textから取消線を除いた文字列を出力し、表示形式を適用できなかったことを結果情報に記録する。取消線の文字を残すためのフォールバックはしない。
- 取消線の除外後に内容がなくなった本文ブロック・表は出力しない。シートは画像も含めて内容がない場合に除外する。表は元の罫線で検出してから内容を除外し、文字の削除だけで表を分割しない。セルの取消線を理由に近くの画像を削除しない。
- reportには除外したセル座標と文字数を記録する。削除した文字や、ラベルが全削除されたリンクの参照先は結果へ含めない。取消線で文字を除外したセルは、診断用の元数式・元の値・元ラベルも結果へ出さず、通常の数式保持ルールよりこの除外を優先する。通常の変換動作として扱い、取消線があるだけでは警告にしない。元のExcelファイルは変更しない。

- 太字はセルのフォントと文字列内の書式区間（rich text）から実効書式を解決する。セル全体の太字、部分的な太字、太字セル内の明示的な通常文字を区別する。隣接する同じ書式の区間はまとめる。
- 数値や数式の表示結果にはセル全体の太字を適用する。表示形式で元の文字列と出力文字列が変わる場合、部分書式の位置を推測して移植せず、セル全体の書式を使い、部分書式を保持できないことを結果情報に記録する。
- 太字区間は改行やセル境界をまたがせない。Markdownの区切り記号が成立しない文字境界は、生成側の `<strong>` を使って文字と太字範囲を保持できるようにする。入力HTMLとは区別してプレビューで扱う。
- 通常のセルハイパーリンクは表示文字列とリンク先を取得し、絶対URLの `https`・`http` と `mailto` をMarkdownリンクにする。表示文字列が空ならリンク先をラベルにし、有効リンクだけを持つセルも内容ありと扱う。
- `HYPERLINK("https://example.com", "詳細")` のような数式も、リンク先が文字列リテラルとして確定する場合は対応する。セル参照や文字列の計算が必要なリンク先は評価せず、保存済みの表示結果を保持して警告する。元数式はキャッシュ欠落時の本文フォールバック以外では保存しない。表示ラベルは保存済みの結果を優先し、結果欠落時はリテラルのラベルを使い、それもなければ確定したリンク先を使う。専用の数式解析で識別し、単純な文字列切り出しや任意の数式再計算は行わない。
- シート・セルへの内部リンク、相対パス、ローカルファイルへのリンクはv1では表示文字として残す。未変換理由とセル座標を結果情報へ保持し、存在しないMarkdownアンカーを作らない。
- その他のスキームや不正なリンク先はリンク化せず、表示文字と診断情報を残す。変換時にリンク先へアクセスしない。
- 太字とリンクを組み合わせたセルは `[**詳細はこちら**](https://example.com)` のように出力する。文字列として書かれただけのURLを独自に自動リンク化しない。
- ラベルの角括弧・アスタリスク・表内のパイプと、URLの括弧・空白などは別々に処理する。入力をエスケープしてから生成側の装飾を付け、Markdown全体を再エスケープして装飾を壊さない。

条件付き書式やテーブルスタイルだけによる太字・取消線はv1では評価せず、罫線と同様に結果情報へ記録する。通常セルの直接書式とrich textを初期の対応範囲とする。図形の線を文字へ重ねて作った取消線は対象外。

```markdown
この項目は**必須**です。

[申請ページ](https://example.com/apply)

|  |  |
| --- | --- |
| **項目** | **説明** |
| 申請方法 | [**手順を確認**](https://example.com/guide) |
```

## 画像

v1の基本対象は、シート上に貼り付けられた通常の埋め込み画像（浮動画像）。画像の文字起こしや説明文の生成は行わず、画像として保持する。

### 抽出と保存

- 表示対象シートの描画オブジェクトを走査し、画像データと配置情報を対応付ける。ブック全体の画像一覧を丸ごと保存せず、未使用・非表示シートの画像を混ぜない。グループ内の画像も再帰的に探索する。後述の図形描画に組み込んだ配置は、単独の画像ブロックとして重複出力しない。
- 抽出できる画像は元形式で保存する。PNG・JPEGをMarkdown画像表示の初期対象とし、WMF・EMF・DIBなどは元形式のファイルリンクと未表示の警告を出す。拡張子だけをPNGへ変えたり、画像変換ライブラリを追加して一律に変換したりしない。
- パスは `images/image-0001.png` のように固定形式で生成し、入力のシート名・画像名をパスとして使わない。拡張子とMIMEは実データと照合し、不明な形式は `.bin` の添付扱いにする。
- 同じ画像データはSHA-256と実バイト列で照合して一つのファイルを共有し、複数の配置位置にはそれぞれ参照を出す。番号はシート順と描画オブジェクトの安定した走査順で決める。
- 代替テキストが保存されていればエスケープして使い、なければ「画像1」のような名前にする。内容を推測して説明を付けない。

### Markdown上の位置

- 左上アンカーの行・列に対応する位置へ画像ブロックを置く。同じ位置の本文は先、複数画像は描画オブジェクト順とする。
- 表に重なる浮動画像は、その表の直後に独立した画像ブロックとして置く。複数の表に重なる場合は、出力順で最後に重なる表の直後に置き、一つの配置を重複出力しない。
- セル座標を得られない絶対位置の画像や、位置を解決できないグループ内画像はシート末尾に置き、配置を再現できないことをreportへ記録する。
- 非表示シート・明示的に非表示の画像は除外する。画像と行列の可視性は必ずしも一致しないため、v1では「左上アンカーの行または列が非表示なら除外」を固定ルールにし、除外理由を記録する。
- 画像の元の縦横比を保持し、Playgroundでは表示領域に収まる幅で表示する。Excel上の拡大率・ピクセル単位の配置・重なり順は再現しない。

### 初期対応の限界

- 元画像の抽出なので、Excel側の切り抜き・回転・反転・画像効果は反映しない。特に切り抜き前の領域も元画像には含まれる。加工を検出した画像には警告を付け、抽出結果をExcelと同じ見た目と扱わない。
- 新しい「セル内に配置」の画像（rich data）や `IMAGE()` 関数は通常の浮動画像と別経路で扱う必要があり、v1の初期対象外とする。検出したものは場所に未対応の表示を残し、reportへ記録する。外部参照の画像をサーバーやプレビューから取りに行かない。
- グラフ・SmartArtの描画、OCRは初期対象外。基本図形の描画は後述の範囲で対応する。図形に重ねた線や貼り付け画像内の取消線の文字を検出して削除する処理は含めない。
- 読み取れない画像は欠落を警告し、その位置に代替テキストと未抽出の表示を残す。画像の存在が理由なく消えないようにする。上限超過の場合は後述の共通ルールどおりジョブ全体を失敗させる。

成果物は次の配置に統一する。画像がない場合は `images/` を省略できる。

```text
document.md
report.json
images/
  image-0001.png
  image-0002.jpg
```

```markdown
# 操作手順

**申請ボタン**を押します。

![申請画面](images/image-0001.png)
```

## 基本図形の簡易描画

POIで図形の種類・配置・文字・書式を読み取り、共通の図形モデルへ変換してJava2DでPNGを生成する。POIにExcel図形の一括PNG変換APIがあるという前提ではなく、対応種類を絞った描画処理をこのアプリで実装する方針。

`XSSFSimpleShape` はスプレッドシート用の `ss.usermodel.SimpleShape` であり、`DrawSimpleShape` が受け取るスライド用の `sl.usermodel.SimpleShape` とは異なる。そのまま `DrawSimpleShape.draw()` に渡せない。DrawingMLの図形情報を一時的なPowerPointへ移す方法は検証候補に留め、テーマ・参照・座標の互換性や `.xls` への適用を未検証のまま必須経路にしない。

### 初期対応範囲

| 対象 | 方針 |
| --- | --- |
| 四角・角丸四角・円・楕円 | 図形の位置と大きさから描画 |
| 直線・直線コネクター・基本的な矢印 | 保存された端点と対応する矢印形状を描画。線の自動引き直しはしない |
| テキストボックス・図形内文字 | 保存されたフォント・サイズ・太字・斜体・RGB/テーマ文字色・通常下線・字間・段落別配置・上下配置・余白・行間・折り返し・縮小・文字回転を反映 |
| 単色の塗りつぶし・線色・線幅 | 保存された値と解決できるテーマ色を反映 |
| 回転・反転・グループの拡大縮小 | 座標変換を共通モデルへ正規化し、対応図形に適用 |
| グラフ・SmartArt・自由曲線・複雑な立体表現 | 初期対象外。検出して警告と代替表示を出す |
| 影・グラデーション・複雑な画像効果・縦書き | 完全再現は初期対象外。省略・簡略化した箇所をreportへ記録 |

`.xlsx` と `.xls` は別の読み取りアダプターから同じ図形モデルへ渡す。公開APIで不足する線・塗りつぶし・接続などはDrawingML／Escherの情報を読む必要がある。形式ごとの対応範囲はfixtureで確認し、取得できない形や書式を無条件に同等対応と扱わない。

### 1枚にまとめる範囲

- 明示的な図形グループは、その中の位置関係・重なり順を保って1枚にする。入れ子グループの座標変換も合成する。
- 未グループの図形は、取得できるコネクターの接続先情報、または描画領域の重なりを根拠に連結した範囲を1枚にする。同じグループは分割しない。単に近くにあるという理由だけでは結合しない。
- つながりを判定できない図形は単独画像にする。接続情報を解釈できなかった線は分割され得るため、そのことをreportへ記録する。全図形を一枚の巨大画像へまとめない。
- 背後のセル文字・セル罫線は図形画像に描かない。本文やMarkdown表との二重出力を避け、図形同士の描画だけを対象にする。
- PNG・JPEGの貼り付け画像が描画範囲の構成要素なら、同じ図形画像へ配置できるようにする。他形式や描画できない要素は代替表示と警告を出し、取り出せる元ファイルは添付リンクとして残す。グループ内の一部欠落を完全な再現結果として扱わない。

### 文字と出力

- 図形内の取消線は文字の書式から判定し、描画前に該当文字を除外する。セルと同じく削除文字をreport・代替テキスト・リンクラベルから復活させない。幾何的な線を重ねた取消線は判定しない。
- 実際の文字を表示できる元フォントが実行環境にあれば優先し、なければ同梱Noto Sans/Serif・Regular/Boldへ置換する。文字色、段落の上下左右配置、余白、字間、折り返しと保存された縮小率を描画へ反映する。特殊な縦書き・WordArt・箇条書き記号などの近似はreportへ記録する。Excel本体とは異なる組版のため、字幅・改行位置の完全一致は保証しない。
- 図形内リンクは取消線の処理後、PNG直後のMarkdownリンクとして残す。画像内の位置別クリック領域は生成しない。
- `images/diagram-0001.png` として保存し、抽出画像と同じHTTP・Queue・Playgroundの経路に載せる。配置は図形全体の左上を基準にし、表と重なれば表直後に置く。内容を判断できない図形は、取得できた文字と未描画の表示を残す。
- キャンバスは変換後の図形・線端・矢印を含む領域と余白から算出する。初期値96dpi相当で透明背景のPNGとし、元の縦横比を保持する。線幅・変換後の範囲・画素数を確認してから画像バッファを確保する。
- 図形数・入れ子深さ・1枚の画素数にも環境変数で上限を設ける。既定値は図形1,000個、深さ16、1枚2,000万画素。1枚ずつ描画・保存し、描画済みの全画像バッファを保持しない。図形PNGは画像バイト数・成果物合計サイズの上限にも含める。画像配置数は埋め込み画像の配置を数え、生成する図形PNGの枚数は図形数の上限で制約する。

## Excel固有の扱い

- 数式の保存済み結果が古いかどうかは原則判定できない。数式は常にキャッシュを利用し、再計算しない。XLSXの結果欠落を識別できた場合は数式をリテラルとして残し、セル座標付きで警告する。欠落を0と断定して補わない。
- 外部ブック、リンク先、マクロ、データ接続の実行・更新はしない。HYPERLINKのリテラル参照先の抽出も再計算ではなく構文解析に限定する。エラー値は `#DIV/0!` などの表示文字列として保持する。
- セルの表示文字列と、元の型・値・数式は内部モデルで分ける。先頭ゼロ付き番号や日付を勝手に数値・ISO日付へ統一しない。列幅で表示される `###` は再現しない。
- 表の空・重複ヘッダーも元の値を保持する。対応表はヘッダー文字列をキーにせず、元の列番号で管理する。
- 入力文字列のMarkdown記号・HTMLをエスケープする。`|` が表を壊したり、セル中の `#` が意図せず見出しになったりしないようにする。改行など生成側の記法と入力を区別する。
- 有効なリンク先はMarkdownに保持し、未変換の診断には値や元URLを保存しない。プレビューには同じリンク先の検証を適用し、入力HTMLやスクリプトを実行しない。
- フィルターは再評価せず、保存された表示状態に従う。印刷範囲でデータを切り捨てない。
- グラフの描画・コメント・ピボットの再計算はv1対象外。グラフには未対応の代替表示と警告を付ける。コメントの本文やピボット定義は出力しない。ピボット結果など通常セルに保存されている値は対象。画像と基本図形は前述の抽出・描画ルールで扱う。

## 変換コアと結果情報

```text
ExcelMarkdownService
  ├─ CellMarkdown: 表示値・太字・リンク・取消線除去
  ├─ BorderTables / MergedRanges: 直接罫線と結合から表を検出
  ├─ DrawingExtractor: 埋め込み画像と図形の読み取り
  │    └─ DrawingScene / DrawingText: 基本図形をJava2D PNGへ
  └─ ConversionWorkspace / ConversionResult: Markdown・画像・report・ZIP
```

Azureに依存しない `ExcelMarkdownService` をHTTPとQueueから呼ぶ。表検出とMarkdown生成を分け、H2以降を表すモデルや任意ルール実行基盤は設けない。本文と表のセルは同じ `CellMarkdown` から、取消線を除外して装飾・リンクを付けた出力文字列を受け取る。

結果は `markdown`・`assets`・`report` に分ける。`report` には変換仕様バージョン、元ファイルのSHA-256、対象・除外シート、警告、各ブロックのExcel範囲とMarkdown行範囲を保持する。画像は保存パス・MIME・サイズ・SHA-256と、配置ごとのシート・アンカー・取得できる加工情報を保持する。図形画像は元の図形IDと、簡略化した描画要素の診断を記録する。表は元の行・列番号の配列を持たせ、非表示列を除外しても元セルへ戻せるようにする。本文には座標情報を混ぜない。

同一ファイル・同一コンバーターバージョン・同一実行設定のMarkdownは同じになるようにする。実行時刻など可変情報は本文へ入れない。

## HTTP・Queue

既存機能と同様にExcelバイナリをHTTPで受け付け、直接Queueでは入力Blobを参照する。ファイル本体のBase64 JSON化はしない。資料ごとの変換ルールやシート指定は不要とし、全表示シートを処理する。

| 入口 | 用途 |
| --- | --- |
| `POST /api/convert` | Excel本体を `application/octet-stream` で受信して同期変換。成果物ZIPを返す |
| `POST /api/jobs` | 同期と同じ入力形式で非同期受付 |
| `GET /api/jobs/{id}` | 状態・結果参照 |
| `GET /api/jobs/{id}/result` | 変換済みMarkdown |
| `GET /api/jobs/{id}/report` | 座標対応表・警告 |
| `GET /api/jobs/{id}/images/{assetName}` | 成功したジョブの画像ファイル |
| `GET /api/jobs/{id}/archive` | Markdown・report・画像をまとめたZIP |

同期は画像の有無によらず `application/zip` で `document.md`・`report.json`・`images/` を返す。Storage設定なしでも画像付きの完全な結果を受け取れるようにする。v1の同期応答はZIPに統一し、Markdown単体・JSON単体の応答モードは設けない。警告件数は応答ヘッダーへも出す。Markdown・画像は一時ファイルへ保存し、同期ZIPはサイズ制限付きメモリ出力にまとめる。Java FunctionsのHTTP応答で必要となる最終バッファも含めてメモリ使用量を検証し、配信が常にストリーミングされる前提にはしない。

PlaygroundはZIPからMarkdown・report・画像を読み、生成された `images/` への画像参照と添付ファイルリンクをローカルのBlob URLへ対応付ける。対応形式は画像としてプレビューし、その他形式はダウンロードとして扱う。ZIP一括ダウンロードも提供する。展開件数と合計サイズを制限し、許可した成果物パス以外や外部画像URLは解決しない。入力由来のリンクとは区別して検証する。新しい結果への切り替え時にBlob URLを解放し、画像は遅延表示する。

直接Queueは専用の `excel2md-jobs` を使用し、画像変換のQueueと混在させない。既存の `version`・`jobId`・`input`・`output`・`filename` の構造を踏襲する。入力・出力参照には登録済みStorageエイリアスを使い、任意URLや接続情報を依頼JSONから受け取らない。

非同期結果は `{prefix}/{jobId}/results/{attemptUUID}/` の下に `document.md`・`report.json`・`images/` を個別Blobとして保存する。Queue側はZIP保存を必須にしない。成功状態に成果物の実パスを記録し、すべての必要なファイルが保存された時点で成功にする。既存のジョブ管理と同様に処理の重複を抑え、成功済みの同一依頼は既存結果を返す。再試行の一時成果物が発生しても、成功結果として参照する試行を一つに確定する。

Markdown中の画像パスは常に相対パスとし、Storageアカウント名・期限付きURL・認証キーを埋め込まない。画像取得APIは成功結果の非公開成果物一覧に登録されたパスだけを扱い、ジョブ結果と同じ認証を適用する。匿名公開は不要。Playgroundの非同期プレビューも認証付きで画像を取得してBlob URLへ変換する。`archive` は保存済みの同じ成果物から必要時にZIPを生成する。

非同期機能は既存と同じく `CONVERSION_STORAGE_CONNECTION_STRING` が設定された場合だけ有効にする。Queue名・状態コンテナー名は `excel2md-jobs` に固定する。起動・配置スクリプトがQueue接続設定と無効化フラグを導出し、Storage未設定時にはホストのQueueリスナーも無効にする。

## 容量と処理方針

入力バイト数、シート数、読み取るセル数、出力へ展開する表セル数、画像数、画像バイト数、出力バイト数に上限を設け、環境変数で変更できるようにする。既定値は入力20MiB・50シート・読み取り20万セル・表展開100万セル・Markdown単体20MiB・画像配置200件・1画像20MiB・成果物合計100MiB（Markdown、report、画像の非圧縮サイズの合計）。画像数は共有ファイル数だけでなく配置数でも制限する。Queueは既存の依頼JSON全体48KiB上限も適用し、画像本体はQueueへ入れない。

これらはアプリ側の既定値であり、4GB環境での性能保証ではない。書式だけのセルや遠く離れたセル、ZIP展開サイズ、共有文字列もメモリに影響する。読み取りセル数は書式のみの実体セルも含め、疎な座標を無条件に巨大な二次元配列へ展開しない。罫線候補の探索にも処理量の上限を設ける。v1はPOIのWorkbookモデルで構造を取得し、大容量用のイベント読み取りは実測後に検討する。

入力・大きな出力は一時ファイルを使い、不要になったら確実に削除する。1インスタンス内の変換同時実行数は初期値1とし、重い変換はQueueで受ける。上限超過は途中までのMarkdownを成功として返さず、明確に失敗させる。

## 受け入れ確認の観点

1. ファイルだけで変換でき、表示シートが順にH1となり、本文からH2以降が発生しないこと。
2. 格子罫線、片側だけの境界、線種の違い、結合セルを含む表の検出。グリッド線・下線・単一囲み枠・罫線のない多列を表にしないこと。
3. 上下左右に並ぶ表、表内の空行・空列、競合・不完全な枠、表外の本文の順序と欠落・重複防止。
4. ヘッダーが確定できない表の全行保持、Excelテーブル定義との一致、複数段見出し、結合・非表示・改行・Markdown記号。
5. 日付・通貨・割合・先頭ゼロ・数式キャッシュ・エラー値・外部参照。本文・表それぞれの全体／部分太字、通常文字への切り替え、リンクとの併用、空白・記号・改行の境界を `.xlsx` と `.xls` で確認。
6. 巨大な疎シート、書式のみの大量セル、罫線探索・ZIP展開・出力の上限。
7. 同期・QueueでMarkdownが一致すること、再試行時の結果とreportの整合性。
8. 原文Excelへ逆引きできる座標対応表、検出限界の警告、安全なプレビュー。Web・メール・内部・ファイルリンク、HYPERLINKの定数／動的な参照先、空ラベル、不正なURLの扱いとリンク先へアクセスしないこと。
9. 全体／部分取消線、通常文字への切り替え、太字・リンクとの重複、全削除したリンクの復活防止、数式結果の除外。表の行列を維持し、削除した文字がMarkdown・プレビュー・reportへ残らないこと。
10. PNG・JPEG抽出、その他形式の添付、画像だけのシート、同じ画像の複数配置、グループ・絶対位置、表との重なり、非表示・加工・未対応画像の扱い。貼り付け画像の中に描かれた文字は取消線除去の対象外であることも確認。
11. 同期ZIPとQueueの個別ファイルで内容・相対参照が一致すること。認証付き画像取得、画像数・容量の上限、欠損画像、画像保存途中の失敗、ZIP展開とプレビューを確認。
12. 基本図形・矢印・日本語の図形内文字、太字・取消線・リンク、テーマ色、回転・反転・グループ座標と重なり順。未グループの接続・重なりによる結合、画像との混在・重複出力防止、非表示、未対応要素、図形数・深さ・画素数の上限を確認する。取消線の削除前／削除済みの参照fixture同士の画像一致や画素・寸法を検証する。Excel本体のスクリーンショットとの網羅的比較は未実施。
