同期HTTP

ファイルを送り、画像を受け取る

1回のPOSTで変換とダウンロードを行います。全ページはZIP、ページを指定した場合は画像1枚を返します。

POST /api/convert — 同期変換

POST/api/convert

認証：Function認証。Azure上では x-functions-key に利用可能なキーを渡します。アプリ用Storageが未設定でも利用できます。既定のルート接頭辞は /api です。

本文はファイルの生バイト列です。 Content-Type: application/octet-stream と --data-binary を使用してください。PDFもこのContent-Typeで送ります。multipartやJSON、Base64文字列では送りません。

リクエストヘッダー

ヘッダー指定
Content-Typeapplication/octet-stream。multipart/* はアプリが415で拒否します。他のContent-TypeはJava workerのバインドで処理できない場合があります。
x-functions-keyAzure上のFunctionキー。複数APIを同じキーで使う場合はHostキーを使用します。masterキーは不要です。
x-file-name任意。クエリに filename がないとき、入力名として使います。

Core Toolsの通常のローカル起動ではFunctionキー認証を強制しません。ローカルで成功しても、Azure上の認証が不要という意味ではありません。

クエリパラメーター

名前型・値省略時意味
filename文字列x-file-name、なければ document出力名の元になる名前。ファイル内容の判定には使いません。
formatpng / jpegpngjpg は指定できません。大文字・小文字は区別しません。
page1以上の整数全ページ1始まりのページ番号。範囲や複数ページは指定できません。
width1以上の整数、px元の物理寸法を96dpi明示した横幅へ拡縮し、縦横比を保ちます。

filename はパスの末尾名へ正規化した後に検査します。HTTPでは最大200文字で、制御文字、空の末尾名、.、.. は使えません。明示した値が空白だけなら既定名になります。

page=、page=all、width=0 は有効な指定ではありません。全ページや自動寸法にする場合は、そのパラメーターを省略してください。整数は32ビット整数の範囲で解析し、実際に描画できる寸法は画素数上限でも制限します。

未定義のクエリは現在の実装では無視します。output.mode=images を付けても個別Blob保存には切り替わりません。個別保存は直接Queueの契約です。

実行例

以下の BASE_URL と FUNCTION_KEY は仮値です。BASE_URL には末尾の /api を含めず、実際の接続先を設定してください。

BASE_URL='https://YOUR_FUNCTION_APP.azurewebsites.net'
FUNCTION_KEY='YOUR_FUNCTION_KEY'

# PowerPointの全ページをPNGのZIPへ
curl --fail-with-body \
  -H "x-functions-key: $FUNCTION_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @slides.pptx \
  "$BASE_URL/api/convert?filename=slides.pptx" \
  --dump-header response-headers.txt \
  --output slides.zip

# PDFの2ページ目を幅1600pxのJPEGへ
curl --fail-with-body \
  -H "x-functions-key: $FUNCTION_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @document.pdf \
  "$BASE_URL/api/convert?filename=document.pdf&page=2&format=jpeg&width=1600" \
  --output document-page-0002.jpeg

入力名に日本語・空白・& などを含める場合は、クエリ値をURLエンコードします。PDFの page=2 は文書内の2枚目を表し、紙面に印字されたページ番号とは別です。

成功レスポンス

成功時は 200 OK とバイナリ本文を返します。JSONにBase64を詰めたレスポンスではありません。

ヘッダー値
Content-Typeapplication/zip、image/png、image/jpeg
Content-Dispositionattachment; filename="slides.zip" など
X-Page-Count変換したページ数。単一ページの指定では 1。
Cache-Controlno-store
X-Content-Type-Optionsnosniff
 
HTTP/1.1 200 OK
Content-Type: application/zip
Content-Disposition: attachment; filename="slides.zip"
X-Page-Count: 3
Cache-Control: no-store
X-Content-Type-Options: nosniff

（ZIPのバイト列）

ファイル名とZIP内の連番は出力名のルールを参照してください。変換開始時に文書全体のページ数を検査するため、1ページだけの指定でも文書全体のページ上限は適用されます。

失敗と再試行

アプリが返す失敗は {"error":{"code":"...","message":"..."}} のJSONです。たとえば、存在しないページは 400 INVALID_PAGE、上限超過は413、暗号化・破損資料は422です。

同じ共通変換サービスが処理中なら 503 CONVERSION_BUSY と Retry-After: 3 を返します。時間を空けて再送してください。詳細なコードはエラー一覧にあります。

同期レスポンスは処理完了まで返りません。Functionsホストの実行時間上限とHTTP経路の応答タイムアウトは別です。処理時間が読みにくい資料には非同期HTTPを利用してください。
