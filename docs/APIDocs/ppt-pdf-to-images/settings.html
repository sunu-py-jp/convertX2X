設定・制限・運用

設定とエラーの読み方

入力・ページ数・画素数・出力容量は環境変数で設定します。非同期の有効化には、アプリ設定とFunctionsホストのQueue設定の両方が必要です。

変換上限

環境変数既定値適用対象
CONVERSION_MAX_INPUT_BYTES20971520（20 MiB）入力ファイルのバイト数
CONVERSION_MAX_PAGES50入力文書全体のページ数。1ページだけの指定でも適用。
CONVERSION_MAX_PIXELS_PER_PAGE16000000出力画像1枚の幅×高さ。描画バッファ作成前に検査。
CONVERSION_MAX_OUTPUT_BYTES104857600（100 MiB）画像・ZIP・個別画像保存の出力容量

これらはPOI・PDFBoxやメモリー4GBプランの仕様上限ではなく、このアプリが設ける上限です。HTTP・Queueとも同じ設定を使います。MiBは1,048,576バイトです。

空・未設定なら既定値を使用します。指定する値は正の整数で、不正な数値は起動エラーになります。ページ数は32ビット整数、入力・出力バイト数と画素数はJava配列に収まる値として最大2,147,483,639まで検査します。この数値まで実際に処理できることを保証するものではありません。

出力方式出力容量上限の意味
1ページ画像エンコードした画像1枚に適用
全ページZIP各エンコード画像と最終ZIPに、それぞれ適用
直接Queueの images各画像に加え、全画像＋manifestの合計にも適用

上限を超える部分だけを切り捨てて成功扱いにはしません。失敗時はエラー、非同期では失敗状態になります。

非同期のオン・オフ

設定制御用接続なし制御用接続あり
CONVERSION_STORAGE_CONNECTION_STRING空・未設定：同期だけ有効Blob・Queueを利用できる接続設定
CONVERSION_QUEUE_CONNECTION_STRINGUseDevelopmentStorage=true制御用接続と同じ値
AzureWebJobs.ProcessConversion.Disabledtruefalse
AzureWebJobs.PoisonConversion.Disabledtruefalse

制御用接続の空白を除いた値が空でなければ、アプリの非同期機能は有効になります。接続できるかを検証してから有効にする方式ではないため、設定誤りや権限不足は実際のStorage操作でエラーになります。

QueueバインドはJava起動前に初期化されます。無効時のエミュレーター形式の値は、バインドを構築できるようにするためのもので、無効化フラグと組み合わせてリスナーを止めます。

ローカルの scripts/run_local.py とAzure向けの scripts/configure_azure_async.py が、この派生設定を生成します。Azureで制御用接続だけを追加・削除して終わらせず、派生設定も一緒に更新してください。設定スクリプトの使い方を参照してください。

ローカル設定例

作業ディレクトリは functions/ppt-pdf-to-images です。初回はJDK 21、Core Tools v4、Python 3.10以上が必要です。Maven Wrapperは同梱されています。

cd functions/ppt-pdf-to-images
cp local.settings.example.json local.settings.json
python3 scripts/run_local.py

local.settings.json がなければexampleを使います。同じ名前の設定が環境変数にあれば、環境変数を優先します。実際のキーを含む設定ファイルはGitへ保存しません。

# 入力100 MiB・文書300ページへ変更して起動
CONVERSION_MAX_INPUT_BYTES=104857600 \
CONVERSION_MAX_PAGES=300 \
python3 scripts/run_local.py

非同期をローカルで試す場合は、別途Azuriteを起動し、CONVERSION_STORAGE_CONNECTION_STRING=UseDevelopmentStorage=true を設定します。起動スクリプトの実行はAzureへのデプロイではありません。

同時実行・メモリー・タイムアウト

設定・動作このプロジェクトの値
Functions実行時間 functionTimeout10分
Queue batchSize / newBatchThreshold1 / 0
dynamicConcurrencyEnabledfalse
HTTP maxConcurrentRequests / maxOutstandingRequests1 / 8
Queue visibilityTimeout / maxDequeueCount1分 / 10
共通変換サービスの同時実行1件。競合時は待ち続けず 503 CONVERSION_BUSY。

ホストのHTTP待機上限を超えたリクエストは429となる設定です。HTTP経路・プロキシ・クライアントの応答タイムアウトは、Functionsの実行時間上限とは別に考慮します。

複数インスタンスが動けば、各インスタンスは並列処理します。1件ずつの変換設定は、アプリ全体で1件だけにする分散ロックではありません。Azure上のスケール設定も含めて調整してください。

入力バイト列、文書モデル、描画画像、ZIP結果はプロセスのメモリーを使います。画像は1枚ずつ処理・解放しますが、ZIP方式はZIP全体をメモリーに保持します。images モードは画像を順次Blobへ保存します。待機中の入力はBlobに置かれます。

入力サイズが同じでも、埋め込み画像・ページ数・フォント・描画内容で時間とピークメモリーは変わります。設定値の引き上げ時は、配置先で実際の資料を測定してください。

エラーレスポンスの形式

アプリが捕捉したHTTPエラーは、ステータスコードと次のJSONを返します。プログラムでは error.code を使い、メッセージ文字列への完全一致には依存しないでください。

{
  "error": {
    "code": "INVALID_PAGE",
    "message": "The requested page does not exist."
  }
}

これは存在しないページを指定した場合の実装上の形式です。説明文は現在英語です。認証、ホストの429、タイムアウトなど、アプリに到達する前後の応答はこのJSON形式とは限りません。

非同期の変換エラーは job.errorCode と job.errorMessage に記録します。GET /api/jobs/{id} が成功して失敗状態を返す場合、HTTPステータスは200です。

「相当」は内部例外の分類です。直接Queueへ投入した処理にはHTTPレスポンスがありません。特に依頼そのものの解析失敗は、ジョブ状態を作成できずログ・poison Queueで確認する場合があります。

一時エラーの再試行上限後は、ジョブ状態の errorCode に PROCESSING_FAILED を記録します。503のHTTP応答には Retry-After: 3 が付きます。400・413・415・422は入力や設定を修正してから再依頼してください。

公開範囲とデータ保持

Playground画面・静的アセット・GET /api/playground/config は匿名です。変換・ジョブ登録・状態確認・結果取得はFunction認証です。公開設定に含めるのは非同期の有効状態、入力容量上限、ページ数上限だけです。

Storageの接続文字列や生の依頼JSONはHTTPエラーへ出力しません。状態APIは内部Blob参照を隠しますが、直接Queueの個別画像モードの結果manifestには取得用のStorage登録名・Blob参照が入ります。

Blobは自動削除しません。入力、状態、結果、送信失敗や処理失敗で残った試行を含め、運用側で保持期間と削除方法を設定します。
