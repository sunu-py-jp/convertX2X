設定・上限・エラー

接続設定、11種類の変換上限、ホストの同時実行設定と、失敗時の確認方法をまとめます。

設定の読み込み

AzureではFunction Appのアプリ設定、ローカルでは起動スクリプトと local.settings.json のValuesを使います。上限は未設定・空白なら既定値です。指定する場合は正の整数にし、件数のint項目はJavaのint範囲内に収めます。不正な設定値は起動・設定読み込み時のエラーになり、既定値へ黙って戻りません。

接続・実行環境の設定

設定未設定時／用途
CONVERSION_STORAGE_CONNECTION_STRING未設定・空白で非同期無効。制御Queue・状態Blob・default入出力の接続文字列
CONVERSION_QUEUE_CONNECTION_STRINGホストのQueueトリガーが読む派生設定。有効時は上記接続、無効時は形式検証用 UseDevelopmentStorage=true
AzureWebJobs.ProcessConversion.Disabled非同期無効時 true、有効時 false
AzureWebJobs.PoisonConversion.Disabled上と同じ。poison用リスナーを切り替える
CONVERSION_INPUT_STORAGE_<ALIAS>入力専用の別Storage接続。未設定・空白は未登録
CONVERSION_OUTPUT_STORAGE_<ALIAS>出力専用の別Storage接続。未設定・空白は未登録
AzureWebJobsStorageFunctionsホスト用Storage。Azureでは別途有効な設定が必要
FUNCTIONS_WORKER_RUNTIMEjava
JAVA_OPTS-Djava.awt.headless=true を設定。既存オプションがあれば保持する

ALIASの接尾辞は [A-Z][A-Z0-9_]{0,31}、DEFAULT以外です。JSONでは小文字名を使います。入力・出力の追加登録だけでは非同期は有効になりません。制御用の接続設定が必要です。

JavaのasyncEnabled判定だけでは、Java起動前に初期化されるQueueトリガーを止められません。接続を追加・削除するときは、Queue用別名と2つのDisabled設定も同時に更新します。

ローカル設定

JDK 21、Python 3、Azure Functions Core Tools v4（func）を用意し、リポジトリのルートから次を実行します。起動スクリプトはMaven Wrapperでビルドするため、初回は依存ファイルを取得できるネットワーク接続も必要です。

cd functions/office2md
cp local.settings.example.json local.settings.json
python3 scripts/run_local.py

起動スクリプトが派生設定を生成します。ローカルのAzureWebJobsStorageが空なら非同期用接続をホスト用にも使用します。Azuriteを使う場合は先に起動し、CONVERSION_STORAGE_CONNECTION_STRINGをUseDevelopmentStorage=trueにします。Playgroundは http://localhost:7072/api/playground です。

既存Azureアプリへの設定反映

作業ディレクトリは functions/office2md。Azure CLIを用意し、az login で対象アプリの設定を変更できるアカウントにログインします。非同期を有効にする場合は、実行するプロセスの環境変数 CONVERSION_STORAGE_CONNECTION_STRING に制御Storage接続を設定して実行します。未設定・空白なら非同期を無効にする操作になります。

python3 scripts/configure_azure_async.py \
  --resource-group YOUR_RESOURCE_GROUP \
  --name YOUR_FUNCTION_APP

このスクリプトはプロセスの環境変数を読み、local.settings.json は読みません。制御接続・Queue別名・2つの無効化設定だけを更新し、無関係なApp Settingsを保持します。別Storage登録と上限は別途設定してください。リソース作成やコードのデプロイは行いません。

環境変数で変更できる全上限

環境変数既定値対象
CONVERSION_MAX_INPUT_BYTES20,971,520入力ファイル20 MiB
CONVERSION_MAX_SECTIONS50Excelのシート数／PowerPointのスライド数。Wordは1文書
CONVERSION_MAX_READ_ITEMS200,000Excelは実体セル数、Wordは本文・参照注のXML要素数、PowerPointは文字数＋段落・Run数
CONVERSION_MAX_TABLE_CELLS1,000,000表を展開したセル数の合計
CONVERSION_MAX_MARKDOWN_BYTES20,971,520UTF-8 Markdown、20 MiB

CONVERSION_MAX_IMAGE_BYTES20,971,520画像・添付1件、20 MiB
CONVERSION_MAX_OUTPUT_BYTES104,857,600成果物合計と生成ZIP、それぞれ100 MiB
CONVERSION_MAX_SHAPES1,000図形数。グループ階層の要素も対象

バイト数の単位は整数bytesです。1 MiB = 1,048,576 bytes。これらはPOI固有の上限ではなく、このアプリの処理・容量制限です。適用中の値は匿名の GET /api/capabilities で確認できます。

旧設定名との互換

CONVERSION_MAX_SECTIONSCONVERSION_MAX_SHEETS

新しい名前が未設定または空白なら旧名を読みます。新旧両方に非空値があれば新しい名前を優先します。reportはspecVersion 2で、旧sheetCount/sheetをsectionCount/sectionへ、HTTPのX-Sheet-CountをX-Section-Countへ変更しています。

固定の作業上限とPlayground上限

Excel・Wordの共有Java2Dレイアウトは、1図形20万文字・2万書式区間・1万段落まで、縮小試算を含め2万行レイアウトまでです。超過は 413 DRAWING_TEXT_LIMIT で失敗し、切り捨てて成功にはしません。PowerPointのPOI描画には文書全体のREAD_ITEMS上限を適用します。Word本文XMLの深さは128を超えると DOCUMENT_DEPTH_LIMIT です。

Playgroundのプレビューは先頭20万文字、ブロックと表セルの合計1万件、警告300件までです。取得・ZIP展開は合計100 MiB、Markdown/report各20 MiB、添付1件20 MiB、添付1,200件までで、サーバー設定が小さければそちらを適用します。画面の表示制限と変換APIの上限は別です。

これらは現在の host.json の値です。Java側もプロセス内の変換を1件ずつ実行します。スケールアウトしたインスタンス間では並列となり、全体で1件ずつ／FIFOを保証しません。ホストの混雑・認証・タイムアウト応答はアプリのJSONエラー形式と異なる場合があります。

4,096 MBのFlex Consumptionを想定した配置手順は利用ガイドにあります。POIモデル・Java・Functionsホスト・ZIPバッファがメモリーを使用し、一時ディスクに出力してもこれらは残ります。ファイルサイズから処理時間を保証する機能はなく、Azureへの配置済み・実機検証済みを示す資料ではありません。

アプリのエラーレスポンス

{
  "error": {
    "code": "JOB_NOT_READY",
    "message": "The job has not completed successfully."
  }
}

messageは入力形式・経路により日本語または英語です。連携側は文言に依存せずHTTPステータスとcodeを扱います。HTTPジョブの状態がfailedの場合は、200レスポンス内のjob.errorCode / job.errorMessageを確認します。

HTTP主なコード意味・対応
400EMPTY_INPUT / INVALID_FILENAME / MISSING_FILENAMEボディやファイル名を修正する
400INVALID_JOB_ID / INVALID_QUEUE_MESSAGEUUID・Queue JSONを修正する
400UNKNOWN_INPUT_STORAGE / UNKNOWN_OUTPUT_STORAGE用途に応じたStorage名を登録する
404JOB_NOT_FOUNDジョブ不在。直接Queueの初回処理前は待つ
404ARTIFACT_NOT_FOUND結果一覧に存在する画像・添付名を使う
409JOB_NOT_READY成功状態になるまで待つ。failedなら理由を確認
409RESULT_CHANGED保存済み成果物が変更された。新規変換が必要
409JOB_ID_CONFLICT別の依頼に使われたID。直接Queueで新しいIDを使う
413INPUT_TOO_LARGE / INPUT_BYTES_LIMIT / INPUT_LIMIT_EXCEEDED入力容量超過。受付・コア・Blob読み取りでコードが異なる
413MARKDOWN_BYTES_LIMIT / OUTPUT_BYTES_LIMIT / OUTPUT_LIMIT_EXCEEDEDMarkdown・成果物合計・ZIP／取得容量の上限超過
413SHEET_LIMIT / SECTION_LIMIT / READ_CELLS_LIMIT / READ_ITEMS_LIMIT / TABLE_CELLS_LIMIT / MERGE_LIMIT文書構造・読み取り項目・表の上限超過
413IMAGE_LIMIT / IMAGE_BYTES_LIMIT / IMAGE_PIXEL_LIMIT / IMAGE_PIXELS_LIMIT / SHAPE_LIMIT / GROUP_DEPTH_LIMIT画像・図形の件数、バイト数、画素数、深さの超過

415RAW_BODY_REQUIREDmultipartではなく生バイト列を送る
415UNSUPPORTED_FORMAT / UNSUPPORTED_DOCUMENT / ENCRYPTED_WORKBOOK対象外形式、拡張子と内容の不一致、暗号化Excelなど

上表には変換コア・Queue処理で発生し、HTTP状態のerrorCodeに現れるコードも含みます。Queueの再試行上限後は PROCESSING_FAILED が記録される場合があります。アプリが返す503には Retry-After: 3 が付きます。

警告とエラーを区別する

成功した変換のwarnings / informationはreportに記録します。例として FORMULA_CACHE_MISSING、BORDER_NOT_TABLE、DRAWING_TEXT_APPROXIMATED、IMAGE_FORMAT_ATTACHMENT、CHART_UNSUPPORTED があります。警告がある200レスポンスを失敗と同一視せず、用途に必要な要素が保持されているかを確認してください。

Managed Identity・通知・保持

接続文字列に加え、CONVERSION_STORAGE__blobServiceUriとCONVERSION_STORAGE__queueServiceUriでMI認証を選択できます。ユーザー割り当てMIはCONVERSION_STORAGE__clientIdを追加します。入力・出力のエイリアスにも同様のBlob URI設定を使えます。

Queueトリガー用のCONVERSION_QUEUE_CONNECTION_STRING__queueServiceUri・__credential=managedidentityと、ホスト用Storageの設定も必要です。ワーカーの起動後に設定してもホストの接続には反映できません。

設定既定・動作
CONVERSION_CREATE_RESOURCEStrue。falseでは必要なコンテナー・Queueを事前作成
CONVERSION_RESULT_QUEUE_<ALIAS>__queueName通知先の登録。__connectionString、または__queueServiceUriと任意の__clientIdも必要
CONVERSION_RESULT_RETENTION_DAYS0（清掃無効）。正の整数で所有成果物を期限後に清掃
CONVERSION_STATE_RETENTION_DAYS0（状態保持）。有効化時は結果保持より長い日数が必要

通知先または保持を設定すると5分ごとの定期処理が動きます。未設定では無効です。入力版不一致は409 INPUT_VERSION_MISMATCH、未登録の通知先は400 UNKNOWN_RESULT_QUEUE、清掃済みの結果は410 JOB_RESULT_EXPIREDです。

RBAC・閉域ネットワーク・ホスト認証・配置先での確認は共通の配置・運用手順を参照してください。実AzureのMI・Private Endpoint接続はローカルテストとは別に検証が必要です。
