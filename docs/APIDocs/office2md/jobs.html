Office → Markdown

非同期HTTP

ファイルを登録してジョブIDを受け取り、完了後にMarkdown・report・画像・ZIPを取得します。

処理の流れ

  1. ファイルをPOSTして登録し、ジョブIDとstatusUrlを保存する。
  2. statusUrlをポーリングし、succeededまたはfailedを待つ。
  3. 成功時だけ返されるURLで、Markdown・report・画像・ZIPを取得する。

すべてのジョブAPIにはStorage設定とFunction認証が必要です。Storage接続が未設定なら 503 ASYNC_DISABLED、Retry-After: 3 を返します。キーは各リクエストの x-functions-key ヘッダーへ渡します。

POST /api/jobs

POST/api/jobs?filename=sample.docx

ボディ・ファイル名・Content-Typeは同期APIと同じです。入力と状態を保存してからQueueへ依頼し、変換完了を待たず202を返します。ジョブIDはサーバーがUUIDで生成します。受付時点では本文の変換が成功することまでは確認していません。

入力ファイルがあるディレクトリで、実行するシェルの環境変数 FUNCTIONS_HOST_KEY にホストキーを設定し、URLを配置先に変更して実行します。

curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.docx \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/jobs?filename=sample.docx'

HTTP受付での保存先は制御Storageの office2md-jobs コンテナーです。入力は {jobId}/input、状態は {jobId}/status.json、成果物は {jobId}/results/{attemptId}/... になります。HTTPから入力・出力Storageや保存先を指定する機能はありません。必要な場合は直接Queueを使います。

GET /api/jobs/{id}

GET/api/jobs/{id}

状態取得は200 JSON、Retry-After: 3 を返します。statusUrlは同一アプリ内の相対URLです。job.status がfailedでも状態取得自体のHTTPコードは200です。

状態意味次の操作
queued登録済み。ワーカーの開始待ち3秒を目安に待って状態取得
running変換・成果物保存中。再試行中もこの状態になる場合がある完了を待つ
succeeded全成果物の保存が完了返されたURLから取得
failed変換不能、上限超過、または再試行上限後の失敗errorCode/errorMessageを確認。再変換は新規ジョブ

jobフィールド意味
id / filenameUUIDと入力の表示ファイル名
createdAt / updatedAtUTCのISO 8601日時
sectionCount / warningCount成功時の件数。成功前・失敗時はnull

HTTP状態APIはStorageのコンテナー名、Blobパス、接続情報を公開しません。存在しないジョブは 404 JOB_NOT_FOUND、UUID形式が不正なら 400 INVALID_JOB_ID です。直接Queueの依頼はワーカーが初めて状態を作るまで404になり得ます。

GET /api/jobs/{id}/result

GET/api/jobs/{id}/result

完成した document.md を返します。Content-Type: text/markdown; charset=utf-8、ダウンロード名は document.md です。ZIPではありません。

GET /api/jobs/{id}/report

GET/api/jobs/{id}/report

完成した report.json を application/json; charset=utf-8 で返します。reportのフィールドを参照してください。画像を取得する場合はassets配列のpathを使います。

GET /api/jobs/{id}/images/{assetName}

GET/api/jobs/{id}/images/{assetName}

完成結果の画像・添付ファイルを1件取得します。例えば assets[].path = images/diagram-0001.png なら、assetsBaseUrl に diagram-0001.png を連結します。成功結果の一覧に含まれないファイルは取得できません。

GET /api/jobs/{id}/archive

GET/api/jobs/{id}/archive

完成したMarkdown・report・全画像を読み出して、その場で document.zip を作ります。応答は application/zip です。ZIPをBlobへ常時保存する仕組みではありません。

取得の共通条件とエラー

成果物エンドポイントはすべて成功済みのジョブが対象です。queued・running・failedは 409 JOB_NOT_READY、ジョブ不在は404です。成果物は Content-Disposition: attachment、Cache-Control: no-store、X-Content-Type-Options: nosniff 付きで返します。

X-Section-Count / X-Warning-Count は同期変換だけのレスポンスヘッダーです。非同期では状態JSONの job.sectionCount / job.warningCount、またはreportを参照します。

保存時から変更された成果物は 409 RESULT_CHANGED になります。出力Blobを編集せず、新しいジョブで変換してください。変換が成功していても、ZIP化や取得時の容量上限で413になる場合があります。

再送・キャンセル・保持期間

POST /jobsにはクライアント指定IDや冪等キーがありません。同じファイルを再POSTすると別ジョブになるため、応答を受け取ったらIDを保存してください。ジョブのキャンセル・削除APIはありません。Playgroundの待機停止もサーバー処理を取り消しません。入力・状態・成果物・失敗試行の清掃は運用側で行います。

ワーカーの一時的な失敗はQueueの再試行に従います。アプリ側の継続できない変換エラーはfailedとなり、以後の同一依頼配送で再変換しません。直接Queueの再送契約も参照してください。
