概要と変換ルール

Excel・Word・PowerPointの内容を、Markdown・画像・変換情報へ取り出します。

実際の変換例を見る →
複雑な入力を含む変換結果を、スクリーンショットとダウンロードできるファイルで確認できます。

できること

Excel・Word・PowerPointを、文章として扱えるMarkdownと、埋め込み画像・図形の画像に変換します。Java 21 / Apache POIを使う独立したAzure Functionsアプリです。同期HTTP・非同期HTTP・直接Queueは同じ変換コアを利用します。

同期HTTP

ファイルを送信し、その応答でZIPを受け取る。

非同期HTTP

ジョブを登録し、状態を確認して成果物を取得する。

直接Queue

外部システムからBlob参照のJSONを投入する。

文字・表・変更履歴

本文と表の太字・HTTP/HTTPS/mailtoリンクを保持します。取消線の文字は出力から除去し、リンクや図形altにも復活させません。箇条書きと番号は元の表示を優先し、Markdown閲覧側の再採番を防ぐため番号をエスケープした文字列として出す場合があります。

表は明示ヘッダーがなければ空のヘッダーを追加し、元の全行を残します。Excelは罫線で通常表を検出してから、同じ行範囲にある左右の値と横並びの表を一つの表へ取り込みます。通常表がない値だけの範囲から表は作りません。実結合と、外枠・上下線があり中の縦線だけがない見た目上の結合は、値を左側へ一度出して続きの列を空欄にします。Wordの入れ子表など、表現できない構造は文字や警告として残します。

Wordは挿入・移動先を保持し、削除・移動元を除外します。参照された脚注・文末脚注だけを [^footnote-N] / [^endnote-N] として末尾へまとめます。削除された段落記号による段落連結や、結合セルの変更履歴からの構造復元は対象外です。

PowerPointは各表示スライドの先頭に、元のスライド番号による [page n] を付けます。Wordは先頭を [page 1] とし、明示改ページ・段落の改ページ前・Wordが保存した改ページ境界を連番にします。Wordのページ組版は再計算しないため、保存されていない自動改ページの位置は追加しません。

同期のZIPには画像がなくてもMarkdownとreportが入ります。非同期では各ファイルを個別Blobとして保存し、ZIPは取得時に生成します。同一カテゴリの同じ画像データは共有しますが、配置ごとのMarkdown参照と説明は残ります。

各形式の type: "diagram" ブロックに図形の nodes と接続の edges を格納します。参考画像があれば path とaltのJSONに対応する metadata も持ちます。添付ファイルは個別の path / metadata を持ちます。

図のフィールド意味

図形IDはExcelではシート内、Wordでは描画ブロック内、PowerPointではスライド内で有効です。資料全体では section / range と組み合わせて識別してください。

Wordはコネクター自身が持つ文字を本文へ出し、該当する edges[] にも type / text / x / y / width / height を追加します。近くの独立した文字を接続のラベルへ割り当てません。

各形式の図形文字と接続を本文へ

Excel・Word・PowerPointの図形内の文字と確認できた接続関係を、画像のaltとは別にMarkdown本文へ出力します。既存の本文・表はそのままに、図ごとの文字・構造JSONと参考画像を添えます。画像をまとめる単位と本文内の位置は形式に合わせます。

形式参考画像の単位本文への配置
Excel明示グループ、または保存された接続先を確認できたコネクターでつながる図。独立した図形は単独図のアンカーに沿ってセル本文・表の間へ。表に重なる図は表の後
Word一つの本文内・浮動描画オブジェクトに属するグループ・描画キャンバス元の描画が属する本文位置
PowerPoint図を含むスライド全体通常本文・表の後

Excelは近さや重なりだけで図をまとめず、セル文字や罫線を参考画像へ取り込みません。Wordは独立した描画オブジェクト同士を合成せず、ページ全体の組版も行いません。

PowerPointでは通常本文・表の後に「図中の項目：」「接続関係（保存情報）：」をMarkdownの文字として出し、スライド全体の参考画像を添えます。図形内の太字・リンクも残り、画像のaltを取り出さなくても検索できます。H2以降は追加しません。接続先の通常テキストボックスも図中の項目へ移し、関係のない本文はそのまま残します。

図中の項目：

- shape-3（長方形）：申請
- shape-4（ひし形）：確認

接続関係（保存情報）：

- shape-5：shape-3「申請」 → shape-4「確認」

接続は保存されたコネクターの接続先IDと矢印から生成します。三角・ステルス・矢印の端点記号で向きを判定し、双方向と向きなしも区別します。丸（●、oval）・ひし形（◆、diamond）は方向判定では矢印なしとして扱います。開始点が oval、終端が triangle なら start-to-end、両端が丸・ひし形なら undirected です。JSONの startArrow / endArrow には元の端点種類を残し、未知の端点記号の direction は unknown とします。近さから接続を推測せず、近くの文字を分岐ラベルへ結び付けません。参照の欠落・除外済みの対象・ID重複・向き不明の端点記号は、本文に「接続関係不明」、レポートに DIAGRAM_CONNECTION_UNRESOLVED を残します。

旧Excel形式 .xls とWordのVMLの線は描画できますが、接続先を推測せず未解決として扱います。

Wordの未対応の基本形状も、読み取れる文字・IDはノードとして残し、画像へ描けなくても保存済み接続を解決できます。折れ線・曲線コネクターは画像では直線で近似し、警告を記録します。グラフ・SmartArtの内部構造は展開しません。

各形式の参考画像は対応する表示要素を、元の重なり順・回転・反転・親グループの変形を反映して描画します。PNG/JPEGも同じ画像へ含め、個別の原本抽出は行いません。それ以外の画像形式は原本添付と警告にします。Excel・Wordの基本図形はJava2Dによる近似描画で、Wordの図形PNGの文字は代表書式による簡易描画です。

Excelの画像の切り抜きや複雑な効果は再現せず、IMAGE_EFFECTS_IGNORED を記録します。Word図形の本文出力はプレーンテキストで、太字装飾やリンク先は保持せず、リンクの表示文字だけを残します。通常の本文・表の太字・リンクの扱いは変わりません。

PowerPointは図を含むスライドにつき1枚です。PNG/JPEGの切り抜きや、保存・継承された単色背景をテーマ参照も含めて反映し、背景指定がなければ白にします。画像・グラデーションなど未対応の背景は白へ置き換え、UNSUPPORTED_SLIDE_BACKGROUND を記録します。外部の背景画像は取得しません。

RAGに取り込む場合：シート・見出し・[page n] を区切りにし、図中の項目と接続関係を同じチャンクへ残す構成を推奨します。分割する場合も接続と参照先の文字を一緒に持たせ、未解決の関係を確定情報として扱わないでください。デモPPTX と 実変換Markdown で確認できます。

画像内に焼き込まれた文字にはOCRを行いません。保存済みの画像説明は文字で残せますが、説明がなければ文字情報は空です。LLMによる補完もありません。参考画像はPOIの描画範囲に限られ、グラフ・SmartArt・数式オブジェクトなどは対象外です。利用可能な元フォントを優先し、不足時は同梱Notoへ置換しますが、字幅・改行位置の完全一致は保証しません。

座標・サイズ・基準の説明

各形式の参考画像のaltは、図の範囲を表す6項目のJSONです。回転は画像へ反映し、回転角はJSONに含めません。図形ごとの情報は nodes を読み取ります。下記はスライド全体を表すPowerPointの例です。

![{"type":"図","text":"","x":0,"y":0,"width":960,"height":540}](images/diagram-0001.png)
参考画像のJSON意味
type / textまとめた図は「図」と空文字列。Wordの単独図形・画像はその種類・文字。個別情報は nodes[].type / text にも保持
x / y描画できた要素を囲む範囲の左上。PowerPointでは0（スライド左上）
width / height描画できた要素を囲む範囲の寸法。PowerPointでは入力スライドの寸法

右がXの正方向、下がYの正方向です。単位はpt（1/72インチ）で固定し、原点・単位のフィールドは出力しません。原点は下記の形式別ルールで解釈します。

altを取得して JSON.parse(alt) で読み取れます。角括弧・文字内の引用符・バックスラッシュなどは \u005B・\u0022・\u005C のようなJSONのUnicodeエスケープで出力するため、Markdownのエスケープを別途解除する必要はありません。レンダリング後の画像の alt もパースできます。直接処理する場合は、report.json の blocks[].metadata に同じ情報があります。

添付ファイルのリンクには個別の形状種類・文字・外接矩形のJSONを付けます。Excel・Wordも同じJSON形式です。図形内の文字はMarkdown本文にも残します。

形式座標の意味
Excelシート左上。セルの幅・高さから算出するため、Excelの表示と丸めの差が出る場合がある
PowerPointスライド左上
Word描画オブジェクト内のローカル座標。本文内・浮動配置の保存指定は図の placement 文字列に分離し、ページ絶対位置は計算しない

小数3桁まで表示します。外接矩形は回転・反転・グループ変形後の範囲で、線幅やPNGの余白は含みません。回転前の寸法やPNGのピクセル数とは別です。不明な位置・寸法は null とし、描画用の仮座標をメタデータへ流用しません。説明は保存値から定型生成し、LLMやOCRは使いません。

座標は構造情報です。MarkdownやPlaygroundは自由配置を行わず、各図の配置は参考画像で確認します。Excelで表と重なる図は表の後、Wordは本文XML順に配置します。

数式・外部参照は実行しない

Excelの数式は関数名にかかわらず再計算しません。保存済みの値があれば古い値やエラーもそのまま扱い、欠落を外部取得で補いません。XLSXでキャッシュがなければ式をエスケープして残し、FORMULA_CACHE_MISSING を記録します。式全体が IMAGE(...) なら画像を取得せず未対応表示にします。

外部画像・外部ブック・データ接続を取得／更新せず、WordのフィールドやPowerPointのリンクも実行しません。許可された通常リンクは、閲覧者がクリックした時だけ開きます。Queue・Blobへの通信は管理者が設定したStorage接続で行います。元ファイルをOffice等で開いた時の動作は、そのアプリ側のものです。

Playground と関連資料

ローカル既定URLは http://localhost:7072/api/playground です。匿名で画面を開けますが、Azureの変換APIにはホストキーが必要です。入力HTMLを実行せず、画像は成果物内だけを表示します。「待機を停止」は通信の停止であり、ジョブのキャンセルではありません。
