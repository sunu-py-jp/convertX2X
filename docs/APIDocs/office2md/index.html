概要と変換ルール

Excel・Word・PowerPointの内容を、Markdown・画像・変換情報へ取り出します。

実際の変換例を見る →
複雑な入力を含む変換結果を、スクリーンショットとダウンロードできるファイルで確認できます。

できること

Excel・Word・PowerPointを、文章として扱えるMarkdownと、埋め込み画像・図形の画像に変換します。Java 21 / Apache POIを使う独立したAzure Functionsアプリです。同期HTTP・非同期HTTP・直接Queueは同じ変換コアを利用します。

同期HTTP

ファイルを送信し、その応答でZIPを受け取る。

非同期HTTP

ジョブを登録し、状態を確認して成果物を取得する。

直接Queue

外部システムからBlob参照のJSONを投入する。

文字・表・変更履歴

本文と表の太字・HTTP/HTTPS/mailtoリンクを保持します。取消線の文字は出力から除去し、リンクや図形altにも復活させません。箇条書きと番号は元の表示を優先し、Markdown閲覧側の再採番を防ぐため番号をエスケープした文字列として出す場合があります。

表は明示ヘッダーがなければ空のヘッダーを追加し、元の全行を残します。Excelは罫線で通常表を検出してから、同じ行範囲にある左右の値と横並びの表を一つの表へ取り込みます。通常表がない値だけの範囲から表は作りません。実結合と、外枠・上下線があり中の縦線だけがない見た目上の結合は、値を左側へ一度出して続きの列を空欄にします。Wordの入れ子表など、表現できない構造は文字や警告として残します。

Wordは挿入・移動先を保持し、削除・移動元を除外します。参照された脚注・文末脚注だけを [^footnote-N] / [^endnote-N] として末尾へまとめます。削除された段落記号による段落連結や、結合セルの変更履歴からの構造復元は対象外です。

PowerPointは各表示スライドの先頭に、元のスライド番号による [page n] を付けます。Wordは先頭を [page 1] とし、明示改ページ・段落の改ページ前・Wordが保存した改ページ境界を連番にします。Wordのページ組版は再計算しないため、保存されていない自動改ページの位置は追加しません。

PowerPointの図形文字と接続を本文へ

PowerPointでは通常本文・表の後に「図中の項目：」「接続関係（保存情報）：」をMarkdownの文字として出し、スライド全体の参考画像を添えます。図形内の太字・リンクも残り、画像のaltを取り出さなくても検索できます。H2以降は追加しません。接続先の通常テキストボックスも図中の項目へ移し、関係のない本文はそのまま残します。

図中の項目：

- shape-3（長方形）：申請
- shape-4（ひし形）：確認

接続関係（保存情報）：

- shape-5：shape-3「申請」 → shape-4「確認」

接続は保存されたコネクターの接続先IDと矢印から生成します。三角・ステルス・矢印の端点記号で向きを判定し、双方向と向きなしも区別します。丸・ひし形の端点記号は向き不明です。近さから接続を推測せず、近くの文字を分岐ラベルへ結び付けません。参照の欠落・除外済みの対象・ID重複・向き不明の端点記号は、本文に「接続関係不明」、レポートに DIAGRAM_CONNECTION_UNRESOLVED を残します。

参考画像は図形を個別に分割せず、図を含むスライドにつき1枚です。対応する表示要素を、元の重なり順・回転・反転・親グループの変形を反映して描画します。PNG/JPEGは切り抜きなどを反映してこの画像へ含め、個別の原本抽出は行いません。それ以外の画像形式は原本添付と警告にします。保存・継承された単色背景はテーマ参照を含めて反映し、背景指定がなければ白にします。画像・グラデーションなど未対応の背景は白へ置き換え、UNSUPPORTED_SLIDE_BACKGROUND を記録します。外部の背景画像は取得しません。

Excel・Wordは従来どおりグループの子要素まで個別に画像化し、埋め込み画像は原本を取り出します。Excelは基本図形をJava2Dで近似描画し、Wordの図形文字は代表書式による簡易描画です。Wordの図形内リンクの別出力は未対応です。

RAGに取り込む場合：[page n] / H1を区切りにし、図中の項目と接続関係を同じチャンクへ残す構成を推奨します。分割する場合も接続と参照先の文字を一緒に持たせ、未解決の関係を確定情報として扱わないでください。デモPPTX と 実変換Markdown で確認できます。

画像内に焼き込まれた文字にはOCRを行いません。保存済みの画像説明は文字で残せますが、説明がなければ文字情報は空です。LLMによる補完もありません。参考画像はPOIの描画範囲に限られ、グラフ・SmartArt・数式オブジェクトなどは対象外です。利用可能な元フォントを優先し、不足時は同梱Notoへ置換しますが、字幅・改行位置の完全一致は保証しません。

座標・サイズ・基準の説明

PowerPointの参考画像のaltは、スライド全体の範囲を表す6項目のJSONです。回転は画像へ反映し、回転角はJSONに含めません。図形ごとの情報は nodes を読み取ります。

![{"type":"図","text":"","x":0,"y":0,"width":960,"height":540}](images/diagram-0001.png)
参考画像のJSON意味
type / text「図」と空文字列。個別の種類・文字は nodes[].type / text に保持
x / y0（スライド左上）
width / height入力スライドの寸法

PowerPointの座標はスライド左上を原点とし、右がXの正方向、下がYの正方向です。単位はpt（1/72インチ）で固定し、原点・単位のフィールドは出力しません。

altを取得して JSON.parse(alt) で読み取れます。角括弧・文字内の引用符・バックスラッシュなどは \u005B・\u0022・\u005C のようなJSONのUnicodeエスケープで出力するため、Markdownのエスケープを別途解除する必要はありません。レンダリング後の画像の alt もパースできます。直接処理する場合は、report.json の blocks[].metadata に同じ情報があります。

添付ファイルのリンクには個別の形状種類・文字・外接矩形のJSONを付けます。Excel・Wordのaltは従来どおり、図形種類・時計回りの回転角・文字・座標・サイズ・基準を含む日本語の説明文で、図形文字を通常本文へ二重に出しません。

形式座標の意味
Excelシート左上。セルの幅・高さから算出するため、Excelの表示と丸めの差が出る場合がある
PowerPointスライド左上
Word本文内のローカル座標と、浮動図形の水平・垂直基準・保存オフセットを区別する。ページ絶対位置は未算出

右がXの正、下がYの正、単位はpt（1/72インチ）、小数3桁まで表示します。外接矩形は回転・反転・グループ変形後の範囲で、線幅やPNGの余白は含みません。回転前の寸法やPNGのピクセル数とは別です。不明な位置は仮の0座標で補わず「不明」「未算出」とします。説明は保存値から定型生成し、LLMやOCRは使いません。

座標は構造情報です。MarkdownやPlaygroundは自由配置を行わず、PowerPointの配置は参考画像で確認します。Excelで表と重なる図形は表の後、Wordは本文XML順に配置します。

数式・外部参照は実行しない

Excelの数式は関数名にかかわらず再計算しません。保存済みの値があれば古い値やエラーもそのまま扱い、欠落を外部取得で補いません。XLSXでキャッシュがなければ式をエスケープして残し、FORMULA_CACHE_MISSING を記録します。式全体が IMAGE(...) なら画像を取得せず未対応表示にします。

外部画像・外部ブック・データ接続を取得／更新せず、WordのフィールドやPowerPointのリンクも実行しません。許可された通常リンクは、閲覧者がクリックした時だけ開きます。Queue・Blobへの通信は管理者が設定したStorage接続で行います。元ファイルをOffice等で開いた時の動作は、そのアプリ側のものです。

Playground と関連資料

ローカル既定URLは http://localhost:7072/api/playground です。匿名で画面を開けますが、Azureの変換APIにはホストキーが必要です。入力HTMLを実行せず、画像は成果物内だけを表示します。「待機を停止」は通信の停止であり、ジョブのキャンセルではありません。
