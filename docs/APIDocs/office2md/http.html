Office → Markdown

同期HTTP

Officeファイルを一度のHTTPリクエストで変換し、Markdown・画像・reportをZIPで受け取ります。

POST /api/convert

POST/api/convert?filename=sample.docx

ファイル本体をリクエストの生バイト列として送ります。処理が完了すると document.zip を返します。変換用のStorage接続は不要です。AzureのFunctionsホスト用Storageは別途設定します。

リクエスト

項目必須指定内容
ボディ必須空でないOfficeファイルの生バイト列。Base64・JSON・multipartではない
filename指定を推奨クエリに実際の拡張子を含む名前。.xlsx / .xls / .docx / .pptx
x-file-name代替filenameクエリが存在しない場合のファイル名ヘッダー
Content-Type推奨application/octet-stream
x-functions-keyAzure上で必須Function認証用キー。非同期も使う場合はアプリ共通のホストキー

filenameを省略し、代替ヘッダーもなければ workbook.xlsx として扱います。Word・PowerPointは実際の拡張子を必ず指定してください。

ファイル名はパス部分を除いた末尾名を使います。HTTP受付では200文字以内で、制御文字や . / .. は受け付けません。クエリにfilenameがあればヘッダーより優先し、空値の場合は既定名へ戻ります。

ページ・横幅・画像形式・変換ルールを指定するオプションはありません。page / width / format など未知のクエリは現在のHTTP実装では無視されます。部分変換が行われたと判断しないでください。multipart/* のボディは 415 RAW_BODY_REQUIRED です。

curl の例

ローカル起動後、入力ファイルがあるディレクトリで実行します。

curl --fail-with-body \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.docx \
  'http://localhost:7072/api/convert?filename=sample.docx' \
  -o document.zip

AzureではURLを配置先に変更し、実行するシェルの環境変数 FUNCTIONS_HOST_KEY にホストキーを設定してから実行します。キーは x-functions-key ヘッダーに渡します。名前に日本語や空白がある場合はクエリ値をURLエンコードします。

curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.pptx \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/convert?filename=sample.pptx' \
  -o document.zip

成功レスポンス

HTTP/1.1 200 OK
Content-Type: application/zip
Content-Disposition: attachment; filename="document.zip"
X-Section-Count: 1
X-Warning-Count: 0
X-Content-Type-Options: nosniff
Cache-Control: no-store

<ZIPのバイト列>
ヘッダー意味
X-Section-Count含まれるシート・スライド数、Wordは文書数
X-Warning-Countreportのwarnings件数。informationの件数は含まない
Content-Dispositionダウンロードファイル名はdocument.zip

ZIPには document.md、report.json、必要な images/... が入ります。成果物の説明を参照してください。警告があっても変換が成功すれば200です。警告とHTTPエラーを区別してください。

失敗レスポンス

HTTP/1.1 415 Unsupported Media Type
Content-Type: application/json; charset=utf-8

{
  "error": {
    "code": "RAW_BODY_REQUIRED",
    "message": "Send the file bytes directly as the request body, not multipart/form-data"
  }
}

アプリ由来のエラーは error.code / error.message を返します。代表例は空ボディ400、入力上限413、対象外形式415、読み取れない文書422、処理内部エラー500です。エラー一覧を参照してください。Azureホストの認証・タイムアウトのエラーはこのJSON形式と異なる場合があります。

同期処理の容量と時間

ZIPは上限付きのメモリーバッファで作成します。HTTPストリーミングではありません。ファイルサイズだけで所要時間は判定できず、同じサイズでも文字・表・図形数で負荷が変わります。時間のかかる資料は非同期HTTPを利用します。

1つのJavaプロセスでは変換を1件ずつ実行します。複数インスタンスでは並列に動作します。functionTimeout の設定は、同期HTTP接続が同じ時間まで維持される保証ではありません。

GET /api/capabilities

GET/api/capabilities

認証なしで、非同期の有効状態・対応形式・適用中の11種類の上限を取得できます。GET /api/playground/config も同じJSONを返します。接続文字列やStorage登録名は返しません。

asyncEnabled は制御Storage接続が設定されているかを示します。Storageへの疎通やQueueリスナーの稼働を確認するヘルスチェックではありません。
