HTML → PowerPoint

同期HTTPで変換

HTMLまたはZIPのバイト列を送り、編集可能なPowerPointを受け取ります。

POST /api/convert

POST/api/convert?filename=input.html&format=zip

本文はmultipartやJSONではなく、生のHTMLまたはZIPです。HTMLファイルの中身を送っても、プログラムで作ったHTML文字列をUTF-8で直接送っても同じです。入出力全体をBase64に変換する必要はありません。

クエリー既定値
filenameinput.html.html / .htm / .zipを含むファイル名。ZIPは必ず拡張子を指定
formatzipzipはPPTX＋report、pptxはPPTX本体のみ
curl --fail-with-body \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @input.html \
  'http://localhost:7077/api/convert?filename=input.html' \
  --output result.zip

HTML文字列を送り、PPTXを保存する

次はNode.jsからの呼び出し例です。Functionキーは呼び出し側のサーバーで管理します。成功時の本文はJSONではなく、PPTXのバイナリです。

import { writeFile } from 'node:fs/promises';

const html = '<h1>上期の報告</h1><p>HTMLから作った資料です。</p>';
const response = await fetch(
  'https://<app>.azurewebsites.net/api/convert?format=pptx',
  {
    method: 'POST',
    headers: {
      'Content-Type': 'text/html; charset=utf-8',
      'x-functions-key': process.env.FUNCTION_KEY,
    },
    body: html,
  },
);
if (!response.ok) throw new Error(await response.text());
await writeFile('presentation.pptx', new Uint8Array(await response.arrayBuffer()));

CSS・画像をまとめて送る

input.zip
├── index.html
├── styles.css
└── assets/
    ├── diagram.svg
    └── product.png

ZIP内の相対パスでCSS・画像を参照します。PNG・JPEGは元データを共有した画像として、SVG素材は検査後に編集可能な図形・文字へ変換します。画像自身のCSS blur(px)は派生PNGを生成し、IMAGE_BLUR_APPLIEDでぼかし量が固定されることを通知します。HTML単体では、style要素・style属性・インラインSVG・Base64の画像data URIを使えます。外部URLやPC上の絶対パスは読み取りません。

<link rel="stylesheet" href="styles.css">
<img src="assets/product.png" alt="製品の画面">
<img src="assets/diagram.svg" alt="システム構成">

アニメーション付きHTML

リクエスト形式・クエリーの追加指定は不要です。HTMLに含まれる@keyframesとanimationを解析し、対応する動きをPowerPointのアニメーションへ変換します。対応範囲と固定出力の規則は機能概要を参照してください。PowerPointのクリック待ちを推測せず、CSSの遅延・時間をスライド開始からの時間として扱います。

<style>
  @keyframes revealCard {
    from { opacity: 0; transform: translateY(40px); }
    to   { opacity: 1; transform: translateY(0); }
  }
  .card { animation: revealCard 1.2s .3s linear both; }
</style>
<div class="card">段階的にサービスを展開</div>

未対応の有限の動きは終端で固定し、ANIMATION_STATIC_FALLBACKと機械判定用の理由をreportへ記録します。無限ループは最初の1回分の終端で固定します。alternateは最初の往路、reverseは逆方向再生の終端を採用します。開始と同じ見た目や透明になる終端も、そのまま保持します。追加オプションは不要です。CSSのtransitionを静止状態で扱う場合はTRANSITION_STATIC_FALLBACKを記録します。警告を確認する用途ではformat=zipを使用してください。入力JavaScript・イベント属性・外部参照の制約は変わりません。

Azureでの認証

Azure上の変換APIはx-functions-keyヘッダーを付けます。キーはURLに含めず、呼び出し側で管理してください。ローカルCore Toolsでは通常キーは不要です。

curl --fail-with-body \
  -H "x-functions-key: $FUNCTION_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @input.zip \
  'https://<app>.azurewebsites.net/api/convert?filename=input.zip&format=pptx' \
  --output presentation.pptx

成功レスポンス

指定HTTPContent-Typeファイル
format=zip200application/zipresult.zip。内部にpresentation.pptxとreport.json
format=pptx200application/vnd.openxmlformats-officedocument.presentationml.presentationpresentation.pptxのみ。警告を確認する場合はZIPを使用

report.jsonのanimations.policyはnative-or-staticです。animations.nativeEffectsにPowerPointの動きへ変換した項目、animations.staticEffectsに固定した項目とreasonを記録します。警告にもANIMATION_STATIC_FALLBACKなどを含めます。対象の特定には項目のidとスライド情報を使用します。ネイティブ項目のsamplingには、method: "computed-css-timing"、sampleCount、easingApproximation: trueを記録します。

report.jsonのfontFamilyはNoto Sans JP、fontPolicyはuniformです。入力のフォント指定にかかわらず、配置計算から出力まで統一します。フォントファイルはPPTXへ埋め込まないため、FONTS_NOT_EMBEDDEDの警告は残ります。

Playgroundと対応情報

入口内容
GET /api/playgroundファイルを選んで変換する簡易画面
GET /api/capabilities入力形式、出力形式、上限値、非同期対応の有無

この2つは匿名で開けます。変換APIの認証は別です。現在asyncはfalseで、ジョブAPI・Queueトリガーはありません。

上限設定

未設定時は以下の値を使います。MBという名前の設定はMiB（1,048,576 bytes）として扱います。Azure Function Appのアプリ設定、ローカルではlocal.settings.jsonのValuesへ設定します。

環境変数既定設定可能な最大値
CONVERSION_MAX_INPUT_MB20 MiB100 MiB
CONVERSION_MAX_UNPACKED_MB100 MiB300 MiB
CONVERSION_MAX_OUTPUT_MB100 MiB300 MiB
CONVERSION_MAX_SLIDES50100
CONVERSION_MAX_DIMENSION_PX4096 px8192 px
CONVERSION_TIMEOUT_SECONDS180秒210秒
CONVERSION_MAX_SHAPES10,00030,000

寸法の下限は64 pxです。ファイル数・DOM数・CSS・画像画素数などの詳細は利用ガイドを参照してください。上限内でも、複雑な入力が制限時間内に変換できることを保証する値ではありません。

上はエラー構造の例です。具体的なmessageは原因に応じて変わるため、呼び出し側ではcodeで判定します。
