Movie → AAC → Blob

抽出した音声をBlobへ保存

動画ファイルまたはHTTPS URLと、書き込み先のBlob SAS URLを受け取り、完成したM4Aを指定先へ保存します。保存完了後にJSONを返す同期APIです。

POST /convert-to-blob単一Blob SAS既存Blobは上書きしない

保存の流れ

動画 + 保存先SAS→AACを抽出→BlobへPUT→201 JSON

入力を一時ファイルに保存し、共通のFFmpeg処理で最初のAAC音声を再エンコードせずにM4Aへコピーします。音声と容量を検証した完成済みファイルをストリームで送信し、Blobの作成成功を確認してから応答します。Queue受付・バックグラウンドジョブではありません。

SAS URLに認証情報が含まれます。
接続文字列、Storageのアカウントキー、任意の認証ヘッダーを追加で渡す必要はありません。Function Appを呼び出す x-functions-key は別の認証情報で、保存先へ転送しません。

保存先を管理者が許可する

Function Appの環境変数に、保存を許可するAzure Blobのホスト名を設定します。未設定・空値では、このAPIは 503 OUTPUT_STORAGE_DISABLED です。

CONVERSION_OUTPUT_ALLOWED_HOSTS=exampleaccount.blob.core.windows.net

Azure公開クラウドの <account>.blob.core.windows.net を完全一致で許可します。最大32件、設定全体8192文字。ワイルドカード、IP、カスタムドメイン、Private Endpoint、dfs エンドポイントは対象外です。コンテナーはあらかじめ作成してください。

URL入力には、取得先を CONVERSION_URL_ALLOWED_HOSTS でも許可します。入力と出力は独立した設定で、同じStorageアカウントでも必要な側へそれぞれ設定します。動画を直接アップロードする場合、入力URLの許可設定は不要です。

URL入力：application/json

POST/api/convert-to-blob

次のJSONを storage-request.json として保存します。sasUrl は発行済みの完全なSAS URLへ置き換えます。下の EXPIRY_UTC と SIGNATURE は構造を示すダミーで、そのままでは使えません。

{
  "input": {
    "url": "https://media.example.com/videos/sample.mp4"
  },
  "output": {
    "sasUrl": "https://exampleaccount.blob.core.windows.net/results/jobs/job-123/audio.m4a?sv=2023-11-03&sr=b&sp=c&spr=https&se=EXPIRY_UTC&sig=SIGNATURE"
  }
}

JSONをコマンドラインへ展開せず、ファイルからボディへ読み込ませます。Azureでは環境変数 FUNCTIONS_HOST_KEY にFunction Appのホストキーを用意します。

curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary @storage-request.json \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/convert-to-blob' \
  --output stored-result.json

JSON全体は最大32KiBです。input.url と output.sasUrl は、それぞれ最大8192文字です。

input.url は既存のURL入力の条件に従います。入力URLにも読み取り用SASを付けられます。保存先SASを入力側の認証に流用することはありません。

ファイル入力：multipart/form-data

動画を直接送る場合は、JSONに input を含めず、次の内容を storage-request.json として保存します。

{
  "output": {
    "sasUrl": "https://exampleaccount.blob.core.windows.net/results/jobs/job-123/audio.m4a?sv=2023-11-03&sr=b&sp=c&spr=https&se=EXPIRY_UTC&sig=SIGNATURE"
  }
}
curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  --form 'request=@storage-request.json;type=application/json' \
  --form 'file=@sample.mp4;type=application/octet-stream' \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/convert-to-blob' \
  --output stored-result.json

パートは request（JSONファイル）と file（動画）の各1つです。request=@… と file=@… は、それぞれJSONと動画をファイルパートとして送ります。ファイル名のないテキストフィールドは受け付けません。境界文字列を含む Content-Type はcurlに生成させてください。

余分なフィールド、同じフィールドの重複、JSONの重複キー・余分なキーは拒否します。元のファイル名は保存先に使わず、sasUrl のパスが保存名を決めます。ローカルではURLを http://localhost:7073/api/convert-to-blob へ置き換えられます。

request のJSONファイルは最大16KiB、動画は CONVERSION_MAX_INPUT_BYTES 以下、multipart本文全体は同上限 + 64KiB以下です。JSONは生のUTF-8として検証します。動画を100MiBちょうど送る場合は、境界文字列やJSON分も収まるよう、Functionsホストの FUNCTIONS_REQUEST_BODY_SIZE_LIMIT を入力上限 + 64KiB以上（既定入力なら 104923136）に設定してください。

受け付けるSASの条件

項目条件
対象URL許可済みAzure Blobホスト、HTTPS、443番ポート。既存コンテナー内の単一Blobの完全なパス
リソース srb のみ。コンテナー・ディレクトリ・アカウント全体のSASは拒否
権限 spc、w、cw のみ。新規作成に必要な c を推奨。読み取り・一覧・削除などを含むSASは拒否
プロトコル sprhttps が必須
バージョン sv2019-12-12 以降
有効期限 se未来のUTC日時が必須。抽出とアップロードが終わるまで有効な短い期間で発行
署名 sig必須。アプリは制約を検証し、署名と最終的なアクセス可否はAzure Storageが検証
その他対応するSASフィールドだけを許可。保存済みアクセスポリシー参照 si、未知・重複クエリ、URL内認証、フラグメントを拒否。任意のPUTヘッダーや接続先IPは指定不可

可能ならMicrosoft Entra IDで発行するユーザー委任SASを使います。サービスSASも単一Blob・上記制約を満たすものだけを受け付けます。SASの発行は呼び出し元システムの役割です。MicrosoftのSASの説明とユーザー委任SASの発行例を参照してください。

SASをFunctionのURLクエリやログへ入れず、HTTPSリクエストのボディで渡します。JSONファイルは秘密情報としてアクセスを制限し、リポジトリに登録しないでください。Movie2AudioはSASを応答・アプリログに出しません。呼び出し側や前段サービスでもリクエスト本文を記録しない設定にしてください。

成功レスポンス：201 Created

{
  "status": "succeeded",
  "output": {
    "blobUrl": "https://exampleaccount.blob.core.windows.net/results/jobs/job-123/audio.m4a",
    "bytes": 9323,
    "contentType": "audio/mp4",
    "etag": "\"0x8DD123456789ABC\""
  },
  "audio": {
    "codec": "aac",
    "mode": "copy"
  }
}

Content-Type: application/json、Cache-Control: no-store で返します。blobUrl はSASクエリを除いた識別用URLで、読み取り権限を付与するURLではありません。必要な読み取り権限は利用側で別に用意します。etag はStorageが返した作成結果です。有効なETagを取得できない場合は、このフィールドを省略します。

上の例では、コンテナーは results、Blob名は jobs/job-123/audio.m4a です。アプリはフォルダー名・ジョブID・接尾辞を追加しません。保存内容は常にM4Aで、BlobのContent-Typeを audio/mp4 に設定します。

既存ファイルと再試行

書き込みは Put Blob、x-ms-blob-type: BlockBlob、If-None-Match: * で行います。既存Blobの上書きはせず、Storageの前提条件エラーを 409 OUTPUT_BLOB_EXISTS として返します。呼び出し側で依頼ごとに一意なBlob名を選び、そのBlob専用のSASを発行してください。

アップロード中の通信切断やタイムアウトでは、Storage側で保存が完了している可能性があります。アプリは自動リトライ、HEADによる存在確認、失敗時のBlob削除をしません。結果が不明なときは保存先を利用側の権限で確認し、同じ名前への再送が409になっても、前回の成果物と同一だと決めつけないでください。

接続と処理の境界

ホスト許可リストとSASの範囲を検証し、DNSの全結果が公開IPであることを確認します。実接続にも検証済みIPを使い、元のホスト名に対するTLS証明書検証を維持します。リダイレクト、プロキシ、Cookie、任意の認証ヘッダー、自動リトライは使いません。

入力・抽出・出力は既存APIと同じ上限とNode.jsプロセス内1件の実行枠を共有します。既定180秒、最大210秒の共通期限にBlobへのアップロード完了も含みます。完成済みM4Aは一時ディスクからストリームでPUTし、成功・失敗後に一時ファイルを削除します。保存先に接続できるStorageのネットワーク設定も必要です。

失敗レスポンス

エラーは既存APIと同じ {"error":{"code":"...","message":"..."}} です。入力・抽出のエラーは共通の一覧、保存先の設定・SAS・競合・通信エラーは以下で判定します。

HTTPcode内容
400INVALID_STORAGE_REQUESTJSONの構造、必須・余分なキー、URL文字列が不正
400INVALID_MULTIPARTパート構造が不正。requestとfileを各1つのファイルパートで送る
400INVALID_OUTPUT_SAS_URL出力URL・SASの対象、権限、期限などが条件外
403OUTPUT_HOST_NOT_ALLOWED / OUTPUT_ADDRESS_NOT_ALLOWED保存先が許可外ホストまたは公開IPではない
403OUTPUT_AUTH_FAILEDStorageがSASやアクセス制限を拒否
409OUTPUT_BLOB_EXISTS保存先Blobが既に存在するため作成できない
413REQUEST_TOO_LARGE / INPUT_TOO_LARGE / OUTPUT_TOO_LARGEリクエスト、動画または音声が上限を超過
415STORAGE_REQUEST_TYPE_REQUIREDapplication/jsonまたはmultipart/form-dataを指定
422OUTPUT_REDIRECT_NOT_ALLOWED保存先のリダイレクトを拒否
502OUTPUT_UPLOAD_FAILED保存成功を確認できない。DNS・TLS・通信・Storage応答を確認
503OUTPUT_STORAGE_DISABLED出力許可ホストが未設定
504CONVERSION_TIMEOUT入力受信からアップロード完了までの期限を超過

Azure Storage実サービスでの保存検証は、ローカルの入力検証・接続設定のテスト・テスト用受信先への転送検証とは別に行ってください。

ジョブIDを受け取って後から結果を取得する場合は 非同期HTTP、他システムから登録済みBlobを処理する場合は 直接Queue を使います。SAS保存APIは同期専用です。
