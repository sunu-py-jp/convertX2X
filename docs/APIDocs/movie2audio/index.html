Movie → Audio

動画から、AAC音声だけを。

動画ファイル、または許可したHTTPS URLを受け取り、最初の音声をM4AまたはWAVで返します。既定のAACコピーは音声データを変更せず、transcodeを明示すると対応形式を変換します。

抽出の流れ

動画 / HTTPS URL→一時ファイル→AACをコピー→audio.m4a

同梱FFprobeで入力内容を確認し、同梱FFmpegで音声トラックを抽出します。音声のビットレート・サンプリングレート・チャンネル数を変更しません。アップロードとURL取得は同じ変換処理・上限・出力形式を使います。

AACは音声コーデック、M4Aは格納形式です。
出力は audio.m4a（audio/mp4）。音声パケットをコピーしますが、元の動画コンテナー・メタデータをそのまま返す処理ではありません。

Azure Speechへの前処理として

入力をストリームで一時ディスクへ保存し、抽出を完了したM4AをHTTPストリームで返します。AACのサンプリングレート・チャンネル数を保持し、faststart でM4Aの再生情報を先頭側へ配置します。抽出と送信は順番に行います。ストリーミングの範囲を参照してください。

現行の対応形式一覧にはAAC、Microsoftの2024年のFast紹介にはM4Aが掲載されています。Azure Speech実サービスでの受け入れ・文字起こしは未検証です。

入力の条件

項目仕様
動画コンテナーMP4・MOV、Matroska、AVI、MPEG-TS、FLV系。拡張子ではなく内容を確認
動画ストリーム必須。カバー画像のみの音声ファイルは動画として扱わない
音声ストリームcopyでは最初の音声がAACであること。transcodeでも後続トラックへ自動で切り替えない
AAC以外copyでは422 UNSUPPORTED_AUDIO_CODEC。transcodeでOpus・MP3・PCM等に対応
対象外Webページ・HLS/DASHプレイリスト・DRMコンテンツ。一般的なFFmpegの全機能は提供しない

動画から動画・字幕・データトラックを除き、入力メタデータとチャプターを引き継がずに音声1トラックを出力します。破損したファイルや、同梱FFmpegの限られた解析範囲で読み取れないファイルは拒否します。

利用するAPI

メソッド / パス入力結果
POST /api/convert動画ファイルの生バイト列audio.m4aを同じレスポンスで返す
POST /api/convert-url{"url":"https://…"}許可済みURLを取得してaudio.m4aを返す
POST /api/convert-to-blob動画またはURL + 出力先SASBlob保存後に201 JSONを返す
POST /api/jobs
POST /api/jobs-url		動画 / URL202で受付・状態確認後にM4Aを取得
Queue movie2audio-jobs入出力Blobを指定するJSON登録済みStorageへM4Aを保存
GET /api/capabilitiesなし / 匿名適用中の上限・URL機能の有効状態

同期HTTP・非同期HTTP・直接Queueの3経路が、同じFFmpeg処理を使います。同期のダウンロードAPIは音声を返し、SAS保存APIは保存完了後に結果JSONを返します。非同期はジョブIDで状態と音声を取得します。

ローカルで試す

Node.js 22または24・npm・Python 3.10以上・Azure Functions Core Tools v4を用意し、リポジトリルートから起動します。FFmpegは同梱済みです。対応環境はLinux x64、macOS Apple Silicon、Windows x64です。

cd functions/movie2audio
npm ci
npm start

Movie2Audio Playgroundへアクセスするか、別のターミナルで動画を送ります。

curl --fail-with-body \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.mp4 \
  'http://localhost:7073/api/convert' \
  --output audio.m4a

既定の上限

入力出力処理期限同時実行
100MiB100MiB180秒（受付・各処理試行・結果取得ごと）Node.jsプロセスごとに1件

上限は環境変数で変更できます。URL取得は CONVERSION_URL_ALLOWED_HOSTS、Blob保存は CONVERSION_OUTPUT_ALLOWED_HOSTS の設定時だけ有効です。非同期HTTP・直接Queueは CONVERSION_STORAGE_CONNECTION_STRING の設定時だけ有効です。これらを未設定でも、ファイルをアップロードして音声を受け取る同期APIを利用できます。

Azure Functions上の性能や処理時間は、動画の長さ・構造・ネットワーク・配置環境によって変わります。メモリー4GBだから100MiBを必ず180秒以内に処理できる、という保証はありません。

音声形式の選択は共通の音声オプションを参照してください。URL・SASの本文形式は変更せず、受付URLのクエリで指定します。
