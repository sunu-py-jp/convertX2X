Movie → Audio

ファイルを送って抽出

動画ファイルのバイト列をPOSTし、最初のAAC音声トラックをaudio.m4aとして受け取ります。

POST /api/convert

POST/api/convert

動画をHTTPのボディに直接入れます。ファイル名・抽出範囲・音声トラック番号・出力形式を指定するパラメーターはありません。

項目指定
ボディ空でない動画の生バイト列。既定上限100MiB
Content-Typeapplication/octet-stream を推奨
x-functions-keyAzureではFunction認証キーが必要。複数APIを使う場合はアプリのホストキー

multipart/* と application/jsonは 415 RAW_BODY_REQUIRED です。ファイルは application/octet-stream、URLのJSONは /convert-url を使います。Base64文字列は動画ファイルの代わりにはなりません。filename など未知のクエリは処理に利用しません。

curl の例

curl --fail-with-body \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.mp4 \
  'http://localhost:7073/api/convert' \
  --output audio.m4a

AzureではURLを配置先に変更します。実行するシェルの環境変数 FUNCTIONS_HOST_KEY にホストキーを設定し、ヘッダーへ渡します。

curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.mp4 \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/convert' \
  --output audio.m4a

Core Toolsでのローカル起動は通常、Functionキー認証を強制しません。Azureホストが返す認証エラーやリクエスト容量エラーは、アプリのエラー形式と異なる場合があります。

成功レスポンス

HTTP/1.1 200 OK
Content-Type: audio/mp4
Content-Disposition: attachment; filename="audio.m4a"
X-Audio-Codec: aac
X-Audio-Mode: copy
X-Content-Type-Options: nosniff
Cache-Control: no-store

<M4Aのバイト列>

X-Audio-Codec: aac は出力音声のコーデック、X-Audio-Mode: copy は再エンコードを行わなかったことを示します。元の動画のファイル名に関係なく、既定の出力名はaudio.m4aです。WAVを選ぶとaudio.wavになります。

ストリーミングの範囲

動画のアップロードは上限付きストリームで一時ディスクへ保存します。FFmpegが音声を抽出し、M4A全体を検証した後、完成したファイルを読み取りストリームで返します。入力動画・出力音声の全体をアプリのメモリーへ読み込む必要はありません。

音声の抽出中から応答するライブ変換ではありません。元のAACを保持した通常のM4Aに faststart を適用し、抽出が完了してから送信します。受信側はHTTP本文をストリームとして読み、保存・再生・次の処理へ渡せます。

アプリは Content-Length を付けません。出力ファイルの読み出し中の期限超過やエラーはストリームを中断し、開始済みの応答をJSONエラーへ差し替えません。転送中のキャンセルはアプリへ伝搬した時点で処理します。利用側ではステータスだけでなく、本文の読み取りが正常終了したことを確認してください。

音声形式を選ぶ

既定はAACの無劣化コピーです。audioMode=transcodeを明示すると、AAC・Opus・MP3・一般的なPCMからM4A/AACまたはWAV/16bit PCMへ変換できます。

クエリ指定値
audioModecopy（既定） / transcode
audioFormatm4a（既定） / wav。WAVはtranscodeのみ
sampleRate省略で元の値。8000 / 11025 / 12000 / 16000 / 22050 / 24000 / 32000 / 44100 / 48000 / 64000 / 88200 / 96000
channels省略で元の値。1〜8

copyではsampleRate・channelsを指定できません。同じパラメーターの重複も拒否します。M4Aへの再エンコードでは音質が変わります。WAVは非圧縮なので、16kHz・16bit・モノラルでも1時間約115MBとなり、既定100MiBの上限を超えます。

curl --fail-with-body \
  'http://localhost:7073/api/convert?audioMode=transcode&audioFormat=wav&sampleRate=16000&channels=1' \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @video.mkv --output audio.wav

同じクエリをURL入力・SAS保存・非同期HTTP受付にも指定できます。直接Queueはversion 2のoptionsを使います。WAVの応答はaudio/wav・audio.wav・X-Audio-Codec: pcm_s16leです。結果取得時に別形式へ再変換はしません。

利用側の例：Azure Speech Fast Transcription

抽出に成功した audio.m4a を、利用側からFastへ送信する例です。Movie2Audio自身はSpeechを呼び出しません。実行するシェルの SPEECH_ENDPOINT にSpeechリソースのエンドポイント（例：https://YOUR_SPEECH_RESOURCE.cognitiveservices.azure.com）、SPEECH_KEY にそのキーを設定してください。Movie2Audio用の FUNCTIONS_HOST_KEY はSpeechには渡しません。

curl --fail-with-body \
  "${SPEECH_ENDPOINT%/}/speechtotext/transcriptions:transcribe?api-version=2025-10-15" \
  -H "Ocp-Apim-Subscription-Key: $SPEECH_KEY" \
  --form 'audio=@audio.m4a;type=audio/mp4' \
  --form 'definition={"locales":["ja-JP"]}' \
  --output transcript.json

Fastのリクエストは multipart/form-data です。Content-Type は境界文字列とともにcurlが生成します。成功時の文字起こし結果を transcript.json に保存します。利用可能なリージョン・音声サイズ・時間上限はFastの公式資料を確認してください。

既定のcopyではAAC音声の再エンコード、サンプリングレート変更、モノラル化は行いません。Fastは既定でチャンネルをまとめ、設定により左右を個別に認識できます。M4Aには -movflags +faststart を適用して再生情報を先頭側へ配置し、Microsoft社員が案内するMP4の読み込み上の注意に対応しています。

Azure Speech実サービスでの受け入れ・文字起こしは未検証です。
現行の対応形式一覧はAAC、Microsoftの2024年のFast紹介はM4Aを掲載しています。この送信例はFast用です。短音声RESTやリアルタイムのSpeech SDKとは入力条件が異なります。

どの音声が選ばれるか

動画の音声構成動作
第1音声AAC、第2音声AAC第1音声だけを抽出
第1音声MP3、第2音声AACcopyでは422。transcodeでは第1音声を変換し、第2音声は選ばない
音声なし422 NO_AUDIO_STREAM
AAC音声のみ、動画なし422 NO_VIDEO_STREAM

失敗レスポンス

{
  "error": {
    "code": "UNSUPPORTED_AUDIO_CODEC",
    "message": "The first audio stream must use AAC in copy mode. Select transcode for supported non-AAC audio."
  }
}

上の例は送信開始前のHTTP 422です。アプリのエラーコードで判定し、音声ファイルとして保存しないでください。設定・エラー一覧にサイズ超過・同時実行・タイムアウトもまとめています。

保存場所と返却方法

一時ディスクへ入力と出力を保存し、完成済みM4Aを読み取りストリームで送信します。ファイル全体をメモリーへ載せませんが、ストリームのバッファとFFmpegは同じインスタンスのメモリーを使います。

出力ファイルの読み取りストリームが正常終了・エラー・伝搬したキャンセル・期限超過で閉じたら、作業ファイルを削除します。このAPIではBlobへ保存しません。出力先SASを渡して保存する場合は、/convert-to-blob を使います。1つのNode.jsプロセスで入力受信からこの読み取りストリームが閉じるまで1件ずつ処理し、競合は 503 CONVERSION_BUSY です。実行・同時処理の設定を参照してください。

ジョブIDを受け取って後から結果を取得する場合は 非同期HTTP、他システムから登録済みBlobを処理する場合は 直接Queue を使います。SAS保存APIは同期専用です。
