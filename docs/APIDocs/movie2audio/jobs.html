Movie → Audio

非同期HTTPで受付・結果を取得する

動画をStorageへ保存してQueueへ登録し、202とジョブIDを返します。ワーカーが抽出したM4Aは、状態APIと結果APIから取得できます。

動画を受付→Blob + Queue→AACを抽出→M4Aを取得

有効化と認証

Function Appに CONVERSION_STORAGE_CONNECTION_STRING を設定すると非同期機能を有効にします。未設定・空値ではジョブAPIを無効にし、Queueトリガーを登録しません。URL入力も使う場合は CONVERSION_URL_ALLOWED_HOSTS が必要です。AzureWebJobsStorage はFunctionsホスト用の別設定です。

受付・状態・結果のすべてにFunction認証を使います。Azureでは同じアプリのホストキーを x-functions-key で渡します。ジョブIDは利用者別のアクセス制御ではなく、このアプリを呼べるキーは他のジョブも参照できます。

POST /api/jobs：動画ファイルを受付

POST/api/jobs

ボディは動画の生バイト列です。multipartやBase64ではなく、同期の /convert と同じ形式で送ります。入力上限を検証して動画をBlobへ保存し、ジョブをQueueへ登録してから202を返します。音声の有無やAAC形式はワーカーが検証します。

curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.mp4 \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/jobs' \
  --output accepted.json

入力の表示名は ?filename=sample.mp4、次に x-file-name ヘッダーを使い、未指定時は video.bin です。両受付APIで共通です。パス成分を除く表示名として扱い、保存先やFFmpegの引数には使いません。日本語名はクエリ値をURLエンコードしてください。

POST /api/jobs-url：動画URLを受付

POST/api/jobs-url
curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  -H 'Content-Type: application/json' \
  --data-binary '{"url":"https://media.example.com/videos/sample.mp4"}' \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/jobs-url' \
  --output accepted.json

JSONは url だけを持つオブジェクトで、最大16KiBです。取得先の許可ホスト・公開IP検証などは 同期URL入力 と共通です。URLからのダウンロードと入力Blob保存は受付リクエスト中に完了します。QueueにはURLやSASを残さず、保存済みBlobの参照を送ります。短時間で失効するURLでも、受付後のキュー待機によって再取得が必要になることはありません。

受付レスポンス

202 Accepted は受付完了で、抽出成功を意味しません。レスポンスの job.id と statusUrl を保存してください。本文は {"job":{…},"statusUrl":"/api/jobs/{id}"} の形です。

{
  "job": {
    "id": "f6603efc-2fa8-4466-8d09-6d7c3ed94c18",
    "status": "queued",
    "filename": "video.bin",
    "createdAt": "2026-09-15T00:00:00.000Z",
    "updatedAt": "2026-09-15T00:00:00.000Z",
    "sizeBytes": null,
    "errorCode": null,
    "errorMessage": null
  },
  "statusUrl": "/api/jobs/f6603efc-2fa8-4466-8d09-6d7c3ed94c18"
}

日時とIDは形式例です。受付応答には状態確認先の Location と Retry-After: 3 ヘッダーも付きます。

jobの項目意味
idUUID形式のジョブID
statusqueued / running / succeeded / failed
filename入力の表示名。出力名は常にaudio.m4a
createdAt / updatedAt作成・更新時刻
sizeBytes成功したM4Aのバイト数。成功前はnull
errorCode / errorMessage失敗時の安全なエラー情報。通常はnull

受付応答を受信できなかった場合も、ジョブが登録済みの可能性があります。HTTP受付を再送すると別のジョブを作成します。呼び出し元でIDを固定して重複依頼を管理したい場合は 直接Queue を使います。

GET /api/jobs/{id}：状態確認

GET/api/jobs/{id}
curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/jobs/JOB_ID'

同じ job と statusUrl を返し、成功した場合にだけ resultUrl（/api/jobs/{id}/result）を加えます。状態Blob内部のStorage登録名・コンテナー・Blob名・接続情報は返しません。failed も状態API自体は正常なJSON応答なので、HTTPステータスだけでなく job.status を確認します。

3秒程度の間隔で確認し、succeeded または failed で終了します。直接Queueへ送った直後は、ワーカーによる状態作成前のため404になる場合があります。

GET /api/jobs/{id}/result：音声取得

GET/api/jobs/{id}/result
curl --fail-with-body \
  -H "x-functions-key: $FUNCTIONS_HOST_KEY" \
  'https://YOUR_FUNCTION_APP.azurewebsites.net/api/jobs/JOB_ID/result' \
  --output audio.m4a

成功した試行のBlobを読み出し、Content-Type: audio/mp4、Content-Disposition: attachment; filename="audio.m4a" で返します。ZIPにはしません。SAS URLへリダイレクトするAPIではなく、Function認証を使って音声本文を受け取れます。状態が成功前なら409、対象ジョブがなければ404です。

ストリームの読み取り途中で接続が切れることがあるため、本文が正常に読み終わったことも確認してください。結果取得を繰り返しても変換は再実行しません。成功状態の公開直後でも、ワーカーの後片付け中などで 503 CONVERSION_BUSY になることがあります。このコードの場合は3秒程度待って取得を再試行します。ジョブの受付を再送する必要はありません。

ジョブAPIの主なエラー

HTTPcode意味・対処
503ASYNC_DISABLED制御用Storage接続が未設定
400INVALID_JOB_IDUUID形式ではないID
404JOB_NOT_FOUND状態がない。直接Queue投入直後は作成前の場合あり
409JOB_NOT_READY結果取得時にまだ成功状態ではない
404RESULT_NOT_FOUND成功結果のBlobが見つからない
409RESULT_CHANGED成功記録後に結果が変更された。Storageの状態を確認
503CONVERSION_BUSY実行枠を使用中。状態・結果取得は時間を空けて再試行
503JOB_STORAGE_ERROR / STORAGE_UNAVAILABLEStorage処理が完了できない。接続・権限・サービス状態を確認

受付時の入力形式・サイズ・URL関連のエラーは 共通エラーを使います。ワーカー内のメディア不備はHTTP受付エラーではなく job.status: "failed" と job.errorCode へ記録します。失敗理由が PROCESSING_FAILED の場合は再試行上限後の状態などを確認します。

保存先と保持期間

対象既定の保存場所
Queuemovie2audio-jobs
入力同名コンテナーの {jobId}/input
状態同名コンテナーの {jobId}/status.json
出力同名コンテナーの {jobId}/results/{attemptUUID}/audio.m4a

HTTP受付は制御用Storageに入出力を保存します。別アカウントの入力・保存先を選ぶ場合は 直接Queueの登録Storage指定 を使います。SAS URLを都度指定したい場合は同期の /convert-to-blob です。

ローカルの作業ファイルは処理後に削除します。既定ではStorageのBlobを自動削除しません。保持設定で所有成果物を清掃できます。状態の保持期限を過ぎると重複判定も終了します。

実行期限とスケール

入力上限・出力上限・AACコピーの仕様は同期と共通です。既定180秒の期限は、HTTP受付、Queueの各処理試行、結果の取得処理にそれぞれ適用します。Queue内での待機時間はこの期限と別です。

Node.jsプロセス内は同期変換とQueue処理を合わせて1件です。Queue設定は batchSize=1、newBatchThreshold=0、動的同時実行は無効です。スケールアウトすれば別インスタンスで並列に処理でき、厳密なFIFO順序は保証しません。インスタンス全体を1つに制限する場合は配置先プラン側でも設定します。

一時的なStorage障害・競合は再試行し、最大10回の後は movie2audio-jobs-poison で失敗状態にします。不正動画や上限超過などは失敗として終了します。重複配送と再試行を参照してください。

Playgroundで試す

Playground で「キューで実行」を選ぶと、この受付・状態・結果APIを順番に使います。Storage未設定時は選択できません。画面は3秒おきに確認し、最大15分で待機を終了します。画面を閉じたり待機を終えたりしても、受付済みのジョブはキャンセルしません。表示されたIDで後から状態を確認できます。

音声形式の選択は共通の音声オプションを参照してください。URL・SASの本文形式は変更せず、受付URLのクエリで指定します。
