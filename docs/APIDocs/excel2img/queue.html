Excel → 画像・PDF

Queueから直接依頼

入力Blobの参照をexcel2img-jobsへ送り、描画結果を個別Blobへ保存します。

メッセージ

{
  "version": 1,
  "jobId": "5b179260-9994-4df6-9d34-cf9638c55431",
  "input": {
    "storage": "default",
    "container": "incoming",
    "blobName": "excel/sample.xlsx"
  },
  "output": {
    "storage": "default",
    "container": "outgoing",
    "prefix": "rendered"
  },
  "filename": "sample.xlsx",
  "options": {
    "format": "png",
    "sheet": "業務フロー",
    "range": "A1:L30"
  }
}

UTF-8 JSON、最大48KiB。ファイル本体や資格情報は含めません。optionsを省略するとPNG、全表示シート、印刷範囲優先です。同じjobIdでオプションだけを変えると競合になります。

出力

rendered/{jobId}/results/{attemptId}/pages/page-001.png
rendered/{jobId}/results/{attemptId}/report.json
rendered/{jobId}/results/{attemptId}/manifest.json

PDFの場合はPNG群がdocument.pdfになります。manifestに成果物パス・MIME型・サイズ・ETag・SHA-256を記録します。

入力版と結果通知

version 2ではinput.expectedETag、最大16件の文字列metadata、登録済みQueueへのnotification.queueを追加できます。結果通知は最低1回配送です。

認証と再試行

Storageはアプリで登録した別名だけを指定します。入力はCONVERSION_INPUT_STORAGE_<ALIAS>、出力はCONVERSION_OUTPUT_STORAGE_<ALIAS>、Managed Identityでは__blobServiceUriを使います。接続文字列を依頼JSONへ入れません。

一時障害は再試行し、確定的なエラーは失敗として記録します。最終的な失敗はexcel2img-jobs-poisonの処理で確定します。
