PowerPoint・PDFを画像へ。Office文書をMarkdownへ。動画をAAC音声へ。
用途に合うAPIを選び、ファイル変換を実行できます。

最初のリクエスト

ローカルでは対象の機能を起動し、ファイル本体をPOSTするだけで試せます。以下はOffice文書をMarkdownへ変換する例です。

  1. 変換機能を起動する

    リポジトリのルートから実行します。以下のOffice変換はJDK 21・Python 3.10以上・Azure Functions Core Tools v4が必要です。Movie → AACはNode.js 22または24・npm・Python 3.10以上・Core Tools v4で起動します。

    cd functions/office2md
python3 scripts/run_local.py

  2. ファイルのバイト列を送る

    別のターミナルで、sample.pptx の場所を指定します。filename には元の拡張子を含めてください。

    POST/api/convert
    curl --fail-with-body \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.pptx \
  'http://localhost:7072/api/convert?filename=sample.pptx' \
  --output document.zip

  3. ZIPを展開して結果を確認する

    document.md・report.json と、画像があれば images/ が入ります。Markdownと画像フォルダーの相対位置を保って利用します。

/api/convert の入力は生のファイルデータです。
Content-Type: application/octet-stream と --data-binary を使います。Movie → AACのURL入力は専用の /api/convert-url へJSONを送ります。Blob保存API /api/convert-to-blob は、動画URLのJSONまたは動画と設定JSONのmultipartに対応します。Base64ファイル入力は提供していません。

呼び出し方を選ぶ

全機能が同期HTTP・非同期HTTP・直接Queueに対応します。Movie → AACはファイルまたはURLを受け付け、非同期では完成したM4AをBlobへ保存します。同期APIではM4AのダウンロードまたはSAS指定先への保存を選べます。

方法使い方アプリ用Storage
同期HTTPファイルを送信し、同じリクエストのレスポンスで成果物を受け取る不要
Movie → AACのBlob保存動画と保存先SASを送り、保存完了後に結果JSONを受け取る保存先のSASと許可ホスト設定
非同期HTTPジョブIDを受領し、状態を確認してから結果をダウンロードする必要
直接Queue入力をBlobへ保存し、参照を含むJSONをQueueへ送る必要
入力Blob→依頼JSONをQueueへ→共通の変換処理→成果物Blob

各機能の非同期は CONVERSION_STORAGE_CONNECTION_STRING を設定した場合だけ有効になります。外部システムから直接Queueへ依頼でき、Playgroundを使う必要はありません。

画像変換の非同期HTTP · Markdown変換の非同期HTTP · 音声抽出の非同期HTTP

ベースURLと認証

機能ローカルのベースURLQueue名
PowerPoint / PDF → 画像http://localhost:7071conversion-jobs
Office → Markdownhttp://localhost:7072office2md-jobs
Movie → AAChttp://localhost:7073movie2audio-jobs

Azureでは配置先の https://<function-app>.azurewebsites.net などに置き換え、変換・ジョブAPIへ x-functions-key ヘッダーを付けます。複数のエンドポイントで使う場合はFunction AppのHostキーを利用します。

BASE_URL='https://<function-app>.azurewebsites.net'
# FUNCTION_KEY は実行環境で設定しておきます。
curl --fail-with-body \
  -H "x-functions-key: $FUNCTION_KEY" \
  -H 'Content-Type: application/octet-stream' \
  --data-binary @sample.pptx \
  "$BASE_URL/api/convert?filename=sample.pptx" \
  --output document.zip

この例のURLはOffice → Markdownの配置先です。ローカルのCore Toolsは通常、Functionキー認証を強制しません。直接QueueはAzure Storage側の認証を使い、FunctionキーをQueueへ入れる必要はありません。

機能ごとの違い

URLのパスが同じでも、受付オプションと結果の形式は機能ごとに異なります。

項目画像変換Office → MarkdownMovie → AAC
同期レスポンス全ページZIP、または指定ページの画像Markdown・report・画像のZIPAAC音声の audio.m4a
変換パラメーターfilename / format / page / widthfilename。ページ・範囲指定なしなし。URL入力APIは url のみ
Queueの成果物画像・ZIP、または画像とmanifestを個別保存Markdown・report・画像を個別保存M4Aを個別Blobへ保存
既定の入力上限20MiB / 文書全体50ページ20MiB / 50シート・スライド。Wordは1文書100MiB / 処理期限180秒
