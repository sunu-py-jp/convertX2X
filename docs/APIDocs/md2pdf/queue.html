Queueから直接依頼

入力Blobの参照をmd2pdf-jobsへ送り、指定Blobへ成果物を保存します。

version 1

{
  "version": 1,
  "jobId": "5b179260-9994-4df6-9d34-cf9638c55431",
  "input": {"storage":"default","container":"incoming","blobName":"markdown/input.zip"},
  "output": {"storage":"default","container":"outgoing","prefix":"converted"},
  "filename": "input.zip"
}

メッセージはUTF-8 JSONで最大48KiBです。jobIdは正規UUID、コンテナー名とBlobパスはAzure Storageの安全な形式にします。資格情報やファイル本体は入れません。

出力場所

converted/{jobId}/results/{attemptId}/document.pdf
converted/{jobId}/results/{attemptId}/report.json
converted/{jobId}/results/{attemptId}/manifest.json

manifestには入力ETag、成果物パス・MIME型・サイズ・ETag・SHA-256を記録します。

version 2

input.expectedETagで入力版を固定し、最大16件の文字列metadataと、登録済み結果Queueのnotification.queueを追加できます。通知は最低1回配送です。

別Storage

storageにはdefaultまたはアプリ設定で登録した別名を使います。入力はCONVERSION_INPUT_STORAGE_<ALIAS>、出力はCONVERSION_OUTPUT_STORAGE_<ALIAS>で役割別に登録します。接続文字列またはManaged Identityの__blobServiceUriを使用できます。

失敗と毒キュー

形式・UTF-8・ZIP・上限など確定的な失敗はジョブをfailedにします。Storageなど一時障害はメッセージを再試行し、最大回数後はmd2pdf-jobs-poisonでPROCESSING_FAILEDへ確定します。
