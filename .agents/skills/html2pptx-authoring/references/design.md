# デザイン判断

## 不要なセカンダリを除く

主張・根拠・関係を一目で掴める資料を作る。余った場所を文章で埋めない。

| 足しがちなもの | 判断と置き換え |
| --- | --- |
| 見出しと同じことをいう副題 | 削除し、本文の開始位置や図の占有面積を調整する |
| 毎ページの「OVERVIEW」「KEY POINT」 | 章の識別として必要な場合だけ残す |
| 3つの論点につけた01・02・03 | 順序がなければ番号を外し、位置と見出しで区別する |
| 小さな注記で説明した比較 | 項目・単位・基準位置を揃え、同じ尺度で並べる |
| 全要素のカード化、枠と影の重ね掛け | 関係のある情報だけまとめる。まず余白と整列で整理する |
| 余白を埋める円・波・アイコン | 題材や情報を示していなければ除く |

「セカンダリ」は不要な重複・飾りを指す。数値の母数・対象期間・出典、矢印の意味、リスク条件など、誤読を防ぐ情報は削らない。すべてを無言の図にすることでも、すべてのページを疎にすることでもない。

## 内容から構成を決める

最初に、読み手がそのページで理解・判断することを短く定める。資料に見せる説明文ではなく制作上の判断として使う。

| 伝えたいこと | 相性のよい構成 |
| --- | --- |
| 変更による違い | 前後を同じ軸で対比。変わった箇所だけ強調 |
| 業務の順序・例外 | 主経路を明瞭にしたフロー。例外経路は線種と短いラベルで区別 |
| 体制・責任分担 | 階層と横断関係を分けた図。上下関係を距離や線で表す |
| 数値や選択肢の比較 | 共通の尺度を持つグラフ、整列した表、直接ラベル |
| 時間と依存関係 | 共通の時間軸に置く。カードの羅列で時間を表さない |
| 製品の具体像 | 内容が読める画面・写真を主役にし、必要な場所だけ注釈 |
| 意思決定・結論 | 主張を大きく置き、判断に必要な根拠へ面積を配分 |

同じ見出し＋三分割を全ページへ適用しない。一方で、変化のためだけに配色・余白・図の記号を毎ページ変えない。比較するページは同じ構成の方がよい場合もある。

## Noto Sans JPで階層を作る

書体選びに個性を依存させず、400/700の太さ、見出しと本文の大きさ、行長、段落間隔、図との比率を調整する。日本語の長い見出しを強い字詰めや全大文字ラベルで飾らない。

1280×720では、例えば見出し40〜56px、本文22〜28px、図表18〜24pxから検討する。これは推奨の出発点でありAPIの制限ではない。閲覧距離や資料密度を考慮し、収まらなければ構成・ページ分割を先に見直す。濃度の低い極小文字へ情報を追いやらない。

見出しの短い1語だけが次行に落ちる場合は、文章・幅・改行位置を調整する。数字・単位・桁の位置を揃える。SVG内の文章は必要ならtspanで行を分ける。

## 装飾を増やさず差を作る

- 参考資料・業務・ブランドから色の役割を決める。背景、主要文字、補助文字、強調、注意などを共通CSSへまとめる。すべてを強調しない。
- 大きな主役と静かな周辺を作る。図を大きく、余白を広く取ることも情報の優先順位になる。
- 意味のないピル、KPI風の大数字、均等カード、グラデーションを既定で追加しない。必要なカードや指定されたグラデーションを一律に禁止するわけではない。
- 写真・ロゴ・アイコンは題材を伝えるものを使う。絵文字や関係のない素材を空間の穴埋めにしない。
- 色だけで状態を区別しない。短いラベルや線種を併用し、本文と背景のコントラストを確保する。

## 最後に見ること

縮小した一覧で、主張とページごとの役割が見えるか。実寸で、文章を追わなくても比較・順序・所属が分かるか。削除しても理解が変わらないラベルが残っていないか。強調が分散していないか。企業名だけを差し替えて無関係な題材にも使える見た目になっていないか。

美観のために重要情報を削らない。最も意味を損なっている箇所から直す。

## 参考にした公開スキル

以下の判断軸を参考に、静的スライドとhtml2pptx向けに書き起こした。外部スキル本体・コードの同梱やインストールは必要ない。Web用の指示を丸ごと適用するものでもない。

| 参考元 | 採用した考え方 | このスキルでの適用 |
| --- | --- | --- |
| [Anthropic frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md) | 題材に固有の表現と、意図のある視覚構造 | 色や配置をブリーフから決め、内容に合う構成を選ぶ |
| [Impeccable](https://github.com/pbakaus/impeccable) | 階層・余白・文字の調整、余分な要素の削減、描画を見た批評 | 作成後に一覧と実寸で見直し、意味を妨げる部分から改善 |
| [Vercel Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md) | 意味のあるHTML、画像寸法、文字の収まりや配置の確認 | table・見出し・明示的な画像サイズを使い、はみ出しを検証 |

Web用のフォント配信、UIの状態管理、スクロール演出、入力フォーム、文字の切り捨てはそのまま採用しない。Noto Sans JP・固定ページ・静的内容・意味を保つページ分割へ置き換える。
