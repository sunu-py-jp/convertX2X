# HTML2PPTX Authoring

静的HTML/CSS/SVGで資料を作り、html2pptxへ渡せるHTMLまたは素材込みZIPとして納品する。文字・図形・表は編集可能な要素、元から画像のものは差し替え可能な画像として保つ。

このフォルダだけで使える。新規生成・見た目の改善では [design.md](references/design.md) を読む。画像・図解・動きの可否は [compatibility.md](references/compatibility.md)、実変換・API送信は [validation.md](references/validation.md) を必要に応じて読む。

## デザインの基準

**不要なセカンダリは排除してデザインに語らせること。**

見出しを言い換えただけの副題、意味のない英語ラベル、バッジ、装飾用の番号、説明のための説明を足さない。大小・余白・整列・色・比較・関係線がすでに伝えている情報は重ねて文章にしない。ただし、結論の根拠、数値の単位、図の凡例、出典、判断条件は必要な情報として保つ。

ブランドと参考資料を優先し、その題材に合う表現を選ぶ。各ページを同じカード群に流し込まない。「AIっぽさをなくす」を、特定の配色・書体・奇抜さの押し付けに置き換えない。Noto Sans JPという制約の中で、サイズ・太さ・行長・余白・配置から個性を作る。

## 作成の進め方

- 読み手、目的、必要な判断、参照資料、ページ数・縦横比の指定を拾う。情報で決められることは進め、結論や数値を作り足して埋めない。
- 各ページの主張と、それを説明する図・比較・表・写真を決める。共通CSSで色・文字・余白を揃えつつ、内容に合った構成を選ぶ。計画やデザイン方針の説明を資料本文に混ぜない。
- [starter.html](assets/starter.html) は入力構造と構成を確認する架空例。毎回同じ文章・色・配置を使う指定ではない。
- 複雑な業務フロー・体制図はSVGの線・図形・テキストで組む。単純な図形の種類だけに制限したり、変換を通すため図全体を画像へ置き換えたりしない。
- 写真・スクリーンショットは実ファイルを同梱する。存在しない画像パスや未完成のBase64を残さない。画像生成や外部素材の利用は依頼の範囲に合わせる。

## 入力として守る条件

1. UTF-8の完全なHTMLにし、各ページに入れ子でない `data-slide` を付ける。ページ順はDOM順。可視の内容をその外へ置かない。
2. 全ページの寸法を揃える。指定がなければ1280×720 CSS pxを使い、`pptx-slide-width` / `pptx-slide-height` のmetaを両方記載する。CSSのページ寸法も同じにする。
3. 各スライドに内容を収める。自動改ページはない。長文や大きな表は意味の切れ目で分け、極端な縮小・省略記号・クリッピングで情報を隠さない。
4. HTML・SVGとも `font-family: "Noto Sans JP", sans-serif` を前提にする。変換時はこのフォントへ統一され、PPTXにはフォントファイルが埋め込まれない。
5. JavaScript、イベント属性、iframe、canvas、動画、フォーム、React等の未実行テンプレートを入れない。Tailwind/CDN等が必要でも、生成時に通常のCSSへ展開して同梱する。
6. 独自の `data-*` は `data-slide` だけ。分類・スタイル・参照にはclass/idを使う。複数ページのSVGのidも文書全体で一意にする。
7. 素材取得の外部URL、端末の絶対パス、外部フォントを使わない。HTML単体ならCSS/SVGをインライン化し、PNG/JPEGは実データのdata URI。ZIPならルートのindex.htmlと相対素材参照を使う。

表現ごとの対応範囲と代替方法は [compatibility.md](references/compatibility.md) に従う。入力エラーを回避するためにAPI側の制限・認証・ブラウザー設定を変更しない。

## 完了の確認

実寸と一覧で、主張の優先順位、文字切れ、余白、図の接続、画像との重なりを確認する。不要な副題や装飾を削った後も意味が通るか見直す。

変換環境が利用できるなら実変換し、reportの固定・近似・警告を確認する。可能ならPPTX側も描画して比較する。HTMLのスクリーンショットを「PPTXの表示結果」と呼ばない。環境がなければHTML/ZIPを渡し、変換・PPTX表示は未検証と明記する。詳細は [validation.md](references/validation.md)。

通常の納品は入力HTMLまたはZIPと、短い確認結果。PPTXも依頼されていれば変換結果を添える。HTMLコードのみを求められた場合は、その形式に従う。
